# 画面に出す文字列（多言語対応）

設定ダイアログ・右クリックメニュー・OSD・エラーの文言を `src/i18n/` に集めてある理由と、
文字列を足すときの手順。Issue #166 の第 1 段階（文字列の一元化）で入れた。
英語の表と言語の設定は第 2 段階で足す。それまで表示は日本語だけ。

## 置き場所と引き方

| 種類 | 置き場所 | 呼び出し側 |
|---|---|---|
| 引数を取らない文字列 | `src/i18n/text.rs` の `texts!` の表 | `Text::MenuQuit.get()` |
| 引数を取る文字列 | `src/i18n/msg.rs` の関数 | `i18n::volume_percent(80)` |
| 現在の言語 | `src/i18n/mod.rs` の `static LANGUAGE`（`AtomicU8`） | `i18n::language()`（`get()` と各関数が中で読む） |

- **キーの打ち間違いはコンパイルで落ちる。** `Text` は列挙子、引数付きは関数名がキーなので、存在しないキーを書けばビルドが通らない。引数の数と型もコンパイラが確かめる
- **使われなくなったキーも CI で落ちる。** 使われない列挙子・関数は `dead_code` の警告になり、`cargo clippy -- -D warnings` がエラーにする
- **言語ごとの表が揃っていることもコンパイラが確かめる。** `Text` の表は `texts!` が言語ごとの `match` を生成し、`msg.rs` の各関数は `match language()` で言語を列挙している。第 2 段階で `Language::English` を足すと、訳が無いキーと関数はすべて「網羅していない `match`」でエラーになる
- テスト（`text.rs` の `mod tests`）は、全キーの文言が空でないこと、前後に空白が無いこと、同じ文言に 2 つのキーが付いていないことを見る

### 引数付きを呼び出し側の `format!` でつながない理由

「`Text` の断片 + 値」を呼び出し側でつなぐと、語順が日本語に固定される。「映像デバイス '{name}' が見つからない」は英語では名前が文の途中に来る。文全体を `msg.rs` の 1 関数で組み立て、言語ごとに `format!` を書き分ける。

例外は記号と空白だけの連結で、`format!("{} {}", NoticeKind::Warning.symbol(), text)` のように記号を前に置くものは呼び出し側に残してある。記号は言語で変わらない。

### 言語を 1 か所の `static` に置く理由

描画だけでなく、エラー型の `Display`（ワーカースレッドで `to_string()` される）からも読む。引数で配り回すと `Display` の外から言語を渡す口が無い。

`OnceLock` ではなく `AtomicU8` にしてあるのは、第 2 段階で設定ダイアログの「適用」から再起動なしに切り替えられるようにするため。`src/ui/` と `src/app/` の子モジュールに `static` を置かない決まり（`GUARDRAIL.md`）はそのままで、**言語の状態だけは `src/i18n/` の 1 つに限る。**

## 選ばなかった案

| 案 | 採らなかった理由 |
|---|---|
| `rust-i18n`（YAML と `t!` マクロ） | proc-macro の依存が増える。キーは文字列なので、打ち間違えても実行時にキーがそのまま画面に出るまで気付けない |
| `fluent` | 翻訳（FTL）を実行時に解釈するので、キーや引数の打ち間違いが実行時まで分からない。依存も増える。得意な複数形や性の扱いは、日本語と英語の 2 言語では要らない |
| 断片をつなぐ自前の `enum` だけ | 上の「呼び出し側の `format!` でつながない理由」のとおり、語順が固定される |

## 入れるもの・入れないもの

**入れるのは画面に出る文字列だけ。** 設定ダイアログ、右クリックメニュー、OSD（音量・ミュート・フルスクリーン・プリセットの切り替え・統計）、映像のプレースホルダー、トーストと「接続状態」タブに出るエラーの文言、ファイルダイアログのフィルタ名。

入れないもの。

- **ログの文言（`log!` 系）。** 読むのは不具合報告を受ける開発側で、ユーザーの言語設定にかかわらず同じ文面で残っているほうが追いやすい
- コードコメント、テストの中の文字列、README
- デバイス名、ファイルパス、ホットキーの表記（`Ctrl+S`）のように、外から来た値や言語に依らない表記
- 単位や形式名だけの文字列（`fps`、`Hz`、`JPEG (.jpg)`）
- 内部のキー（`audio::DEFAULT_DEVICE_KEY`）。キャッシュを引くための値で、画面には出ない
- `src/logging.rs` のエラー文。ロガーを初期化する前の失敗で、画面にもログにも出ない（`docs/design/logging.md`）
- フェイク / モックのデバイスが返す名前と失敗の理由（`video/fake.rs` / `audio/fake.rs` / `app/backend/mod.rs`）。開発時に環境変数で有効にしたときだけ出る

**ログと画面で同じ関数を使っている箇所は、ログも表示の言語に従う。** `AudioDirection::label()` と `video::capture` の `format_actual_video` がそれで、どちらもログと画面の文言を揃えるために 1 つにしてある。言語を切り替えるとログのその部分だけが切り替わるが、分けると画面とログで食い違うので揃えるほうを取った。

## 文字列を足すときの手順

1. 引数が無いなら `src/i18n/text.rs` の `texts!` に 1 行足す。使う場所の塊の末尾に置き、キーは `UpperCamelCase` で「どこの何か」が分かる名前にする

   ```rust
   MenuQuit { ja: "終了" },
   ```

2. 引数があるなら `src/i18n/msg.rs` に関数を足す。値をそのまま差し込むだけの引数は `impl Display` で受け、書式指定が要る数値だけ具体的な型にする

   ```rust
   pub fn volume_percent(volume: i32) -> String {
       match language() {
           Language::Japanese => format!("音量: {volume}%"),
       }
   }
   ```

3. 呼び出し側は `use crate::i18n::{self, Text};` で取り込み、`Text::<キー>.get()` か `i18n::<関数>(..)` を渡す
4. **同じ文言が既にあるならキーを使い回す。** 同じ文言に 2 つのキーを作ると `text.rs` のテストが落ちる。意味が違うのに日本語が偶然同じ場合は、どちらかの言い回しを変えるか、テストの判断を見直す
5. 第 2 段階以降は、足したキーと関数に全言語の訳を入れないとビルドが通らない

エラー enum の文言も同じ手順で足し、その型の `Display` から呼ぶ（`docs/design/error-reporting.md`）。

## 第 2 段階への申し送り

- **`egui` の Id が表示文字列から作られている箇所がある。** `egui::Window::new("設定")` と `egui::ComboBox::from_label(..)` は、渡した文字列がそのまま Id になる。実行中に言語を切り替えると Id が変わり、ウィンドウの位置やコンボボックスの開閉状態が引き継がれない。切り替えを入れるときは `.id(..)` / `from_id_source(..)` で固定の Id を渡す
- **スクリーンショット設定タブの説明 2 つ（`DestinationHint` / `SaveFormatHint`）は 2 行目に字下げの空白を含む。** 置き換える前のリテラルがソースの字下げごと文字列に入れていたもので、表示を変えないためにそのまま移した。訳を入れるときに揃え直す
- 既存のテストに「`Display` の文言が日本語を含むこと」を見るものがある（`audio/mod.rs` / `screenshot.rs` / `hotkey/parse.rs` / `settings.rs` / `keyboard_hook.rs`）。言語を切り替えるテストを足すときは、`LANGUAGE` がプロセス全体で共有されることに注意する（並列に走る他のテストの結果が変わる）
- 設定に言語（自動 / 日本語 / 英語）を足し、`README.en.md` の「UI は日本語のみ」の注記を直す
