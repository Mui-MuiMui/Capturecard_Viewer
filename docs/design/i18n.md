# 画面に出す文字列（多言語対応）

設定ダイアログ・右クリックメニュー・OSD・エラーの文言を `src/i18n/` に集めてある理由と、
文字列を足すときの手順、言語の切り替え方。Issue #166 の第 1 段階（文字列の一元化）で仕組みを入れ、
第 2 段階で英語の表と言語の設定を足した。持っている言語は日本語と英語。

## 置き場所と引き方

| 種類 | 置き場所 | 呼び出し側 |
|---|---|---|
| 引数を取らない文字列 | `src/i18n/text.rs` の `texts!` の表 | `Text::MenuQuit.get()` |
| 引数を取る文字列 | `src/i18n/msg.rs` の関数 | `i18n::volume_percent(80)` |
| 現在の言語 | `src/i18n/mod.rs` の `static LANGUAGE`（`AtomicU8`） | `i18n::language()`（`get()` と各関数が中で読む） |

- **キーの打ち間違いはコンパイルで落ちる。** `Text` は列挙子、引数付きは関数名がキーなので、存在しないキーを書けばビルドが通らない。引数の数と型もコンパイラが確かめる
- **使われなくなったキーも CI で落ちる。** 使われない列挙子・関数は `dead_code` の警告になり、`cargo clippy -- -D warnings` がエラーにする
- **言語ごとの表が揃っていることもコンパイラが確かめる。** `Text` の表は `texts!` が 1 行に `ja` と `en` の両方を要求し、片方が欠けるとマクロの形に合わずに落ちる。`msg.rs` の各関数は `match language()` で言語を列挙しているので、言語を足すと訳が無い関数はすべて「網羅していない `match`」でエラーになる
- テスト（`text.rs` の `mod tests`）は、全キーの文言が全言語で空でないこと、前後に空白が無いこと、2 行目以降に字下げが無いこと、英語の表に日本語の文字が残っていないこと（言語名の「日本語」を除く）、日本語で同じ文言に 2 つのキーが付いていないことを見る。英語では重複を見ない。日本語で言い分けている語（「ビデオ設定」と「映像」）が英語では同じ語（Video）になることがあるため

### 引数付きを呼び出し側の `format!` でつながない理由

「`Text` の断片 + 値」を呼び出し側でつなぐと、語順が日本語に固定される。「映像デバイス '{name}' を開けない」は英語では「Cannot open video device '{name}'」で、名前が文の途中に来る。文全体を `msg.rs` の 1 関数で組み立て、言語ごとに `format!` を書き分ける。

`Text` の語を文へ差し込む関数（`AudioDirection::label()` の「Input」、`Text::SampleRate` の「Sample rate」）は、英語では文の途中に入れるときに `mid_sentence` で小文字にする。`Text` の側は見出しやラベルとして単独で使うので、文頭の形で持つ。

例外は記号と空白だけの連結で、`format!("{} {}", NoticeKind::Warning.symbol(), text)` のように記号を前に置くものは呼び出し側に残してある。記号は言語で変わらない。

### 複数行の文言は `\n` で書く

リテラルの中で改行すると、次の行のソースの字下げまで文字列に入って画面に出る（Issue #225）。`"1 行目。\n2 行目。"` のように 1 行のリテラルに `\n` で書く。`text.rs` のテストが 2 行目以降の字下げを検出する。

### 言語を 1 か所の `static` に置く理由

描画だけでなく、エラー型の `Display`（ワーカースレッドで `to_string()` される）からも読む。引数で配り回すと `Display` の外から言語を渡す口が無い。

`OnceLock` ではなく `AtomicU8` にしてあるのは、設定ダイアログの「適用」から再起動なしに切り替えるため。`src/ui/` と `src/app/` の子モジュールに `static` を置かない決まり（`GUARDRAIL.md`）はそのままで、**言語の状態だけは `src/i18n/` の 1 つに限る。**

## 言語の切り替え

設定の `ui.language`（`settings::LanguageSetting`）は「自動 / 日本語 / 英語」の 3 つで、設定ファイルには `language = "auto"` / `"ja"` / `"en"` と書く。既定は自動。知らない値が書かれていたら自動として扱い、他の項目は残す（色空間と同じ）。実際に使う言語（`i18n::Language`）とは型を分けてある。こちらは「自動」を持ち、OS の言語と合わせて初めて 1 つに決まるため。

- **自動のときは OS の表示言語で決める。** `platform::os_ui_language` が `GetUserDefaultUILanguage` の主言語を見て、日本語なら日本語、それ以外は英語にする。地域の書式（`GetUserDefaultLocaleName`）は見ない。英語の Windows で日付や通貨の書式だけ日本にしている人に日本語の画面を出さないため
- **OS への問い合わせは起動時に 1 回だけ。** 結果は `CaptureCardViewer::os_language` に持つ。Windows の表示言語は変えてもサインアウトまで反映されないので、実行中に問い合わせ直す意味が無い
- **言語を書き換えるのは 2 か所だけ。** 起動時（`CaptureCardViewer::default` で設定を読んだ直後。以降に作る文言が設定の言語で出る）と、設定ダイアログの「適用」「OK」（`app::settings_dialog` の `apply_language`）。`i18n::set_language` で `LANGUAGE` を書き換えるだけで、次に文字列を引いたところから切り替わる
- **ダイアログで選んだだけでは切り替わらない。** 選んだ値はドラフトへ入り、他の設定と同じく「適用」「OK」で反映する。選んだ瞬間に切り替えると、「キャンセル」で閉じたときに戻す先が分からなくなる
- `commit_draft` は `language` を無条件に反映し、`draft_from_imported` は読み込んだファイルの値を採る。ダイアログの外から変わらない項目なので、ホットキーと同じ扱い
- プリセットには入れない（`docs/design/presets.md`）
- 言語名は、表示中の言語にかかわらずその言語自身の表記（「日本語」「English」）で出す。「その他」タブの見出しも日本語のときは「言語（Language）」にしてある。読めない言語へ切り替えてしまっても、戻す場所を見つけられるようにするため

### egui の Id を表示文字列から作らない

`egui::Window::new(title)` と `egui::ComboBox::from_label(label)` は、渡した文字列から Id を作る。実行中に言語を切り替えると Id が変わり、ウィンドウの位置や大きさ、一覧の開閉状態が引き継がれない。設定ダイアログは「適用」の直後に別のウィンドウとして扱われ、初期位置へ飛ぶ。

そのため固定の Id を渡している。

| 箇所 | Id |
|---|---|
| 設定ダイアログ（`ui/mod.rs`） | `.id(Id::new("settings_dialog"))` |
| ホットキー入力ダイアログ（`ui/hotkey_capture.rs`） | `.id(Id::new("hotkey_capture_dialog"))` |
| ビデオデバイス・オーディオ入力・出力の一覧（`ui/device_tab.rs`） | `ComboBox::new("video_device_combo", ..)` など |
| 言語の一覧（`ui/other_tab.rs`） | `ComboBox::from_id_source("language_combo")` |

**`Window` と `ComboBox` を足すときも、Id を表示文字列に頼らないこと。** 右クリックメニューのサブメニュー（`ui.menu_button`）も表示文字列から Id を作るが、言語を切り替えるのは設定ダイアログからで、そのときメニューは閉じているので問題にならない。

### テストから言語を切り替える

`LANGUAGE` はプロセス全体で共有されるので、テストから `set_language` を呼ぶと並列に走る他のテスト（`Display` の文言が日本語であることを見るもの。`audio/mod.rs` / `screenshot.rs` / `hotkey/parse.rs` / `settings.rs` / `keyboard_hook.rs` / `video/mod.rs`）の結果が変わる。**テストでは `i18n::with_language(Language::English, || ..)` を使う。** そのスレッドだけの上書き（`#[cfg(test)]` の `thread_local!`）で、抜けるときに戻す。

## 選ばなかった案

| 案 | 採らなかった理由 |
|---|---|
| `rust-i18n`（YAML と `t!` マクロ） | proc-macro の依存が増える。キーは文字列なので、打ち間違えても実行時にキーがそのまま画面に出るまで気付けない |
| `fluent` | 翻訳（FTL）を実行時に解釈するので、キーや引数の打ち間違いが実行時まで分からない。依存も増える。得意な複数形や性の扱いは、日本語と英語の 2 言語では要らない |
| 断片をつなぐ自前の `enum` だけ | 上の「呼び出し側の `format!` でつながない理由」のとおり、語順が固定される |
| `sys-locale` などのクレートで OS の言語を取る | `winapi` は既に直接の依存で、`GetUserDefaultUILanguage` 1 つで足りる。依存を増やすほどの処理ではない |

## 入れるもの・入れないもの

**入れるのは画面に出る文字列だけ。** 設定ダイアログ、右クリックメニュー、OSD（音量・ミュート・フルスクリーン・プリセットの切り替え・統計）、映像のプレースホルダー、トーストと「接続状態」タブに出るエラーの文言、ファイルダイアログのフィルタ名。

入れないもの。

- **ログの文言（`log!` 系）。** 読むのは不具合報告を受ける開発側で、ユーザーの言語設定にかかわらず同じ文面で残っているほうが追いやすい。ログは日本語で固定
- コードコメント、テストの中の文字列、README
- ウィンドウのタイトル（`Capturecard Viewer`）。製品名なので訳さない
- デバイス名、ファイルパス、ホットキーの表記（`Ctrl+S`）のように、外から来た値や言語に依らない表記
- 単位や形式名だけの文字列（`fps`、`Hz`、`JPEG (.jpg)`）
- 内部のキー（`audio::DEFAULT_DEVICE_KEY`）。キャッシュを引くための値で、画面には出ない
- `src/logging.rs` のエラー文。ロガーを初期化する前の失敗で、画面にもログにも出ない（`docs/design/logging.md`）
- フェイク / モックのデバイスが返す名前と失敗の理由（`video/fake.rs` / `audio/fake.rs` / `app/backend/mod.rs`）。開発時に環境変数で有効にしたときだけ出る

**ログと画面で同じ関数を使っている箇所は、ログも表示の言語に従う。** `AudioDirection::label()` と `video::capture` の `format_actual_video` がそれで、どちらもログと画面の文言を揃えるために 1 つにしてある。言語を切り替えるとログのその部分だけが切り替わるが、分けると画面とログで食い違うので揃えるほうを取った。

**切り替える前に作った文言は切り替わらない。** 記録済みのエラーの本文（`RecordedError::message`。トーストと「接続状態」タブに出る）と、「その他」タブの操作結果の 1 行は、起きた時点の言語で文字列にして持っている。発生源ごとの定型文（`ErrorSource::headline`）は描くたびに引くので切り替わる。本文は次に同じ失敗が起きたときから新しい言語になる。

## 文字列を足すときの手順

1. 引数が無いなら `src/i18n/text.rs` の `texts!` に 1 行足す。使う場所の塊の末尾に置き、キーは `UpperCamelCase` で「どこの何か」が分かる名前にする

   ```rust
   MenuQuit { ja: "終了", en: "Quit" },
   ```

2. 引数があるなら `src/i18n/msg.rs` に関数を足す。値をそのまま差し込むだけの引数は `impl Display` で受け、書式指定が要る数値だけ具体的な型にする

   ```rust
   pub fn volume_percent(volume: i32) -> String {
       match language() {
           Language::Japanese => format!("音量: {volume}%"),
           Language::English => format!("Volume: {volume}%"),
       }
   }
   ```

3. 呼び出し側は `use crate::i18n::{self, Text};` で取り込み、`Text::<キー>.get()` か `i18n::<関数>(..)` を渡す
4. **同じ文言が既にあるならキーを使い回す。** 日本語で同じ文言に 2 つのキーを作ると `text.rs` のテストが落ちる。意味が違うのに日本語が偶然同じ場合は、どちらかの言い回しを変えるか、テストの判断を見直す
5. 英語の訳は UI の文脈に合う自然な英語にする。専門用語（YUY2、WASAPI、Media Foundation、fps、Hz）は訳さない

エラー enum の文言も同じ手順で足し、その型の `Display` から呼ぶ（`docs/design/error-reporting.md`）。
