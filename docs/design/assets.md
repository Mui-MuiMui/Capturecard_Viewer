# アセットの埋め込みとパスの解決

アイコンと既定の効果音を実行ファイルへ埋め込んである理由と、
外部ファイルを読む唯一の経路（設定に保存された効果音のパス）の解決の仕方。

## アセットは exe に埋め込んである

`icon.ico` と既定の効果音 `sound/SS.mp3` は `include_bytes!` で実行ファイルに埋め込んである。ファイルとして読みに行かないため、カレントディレクトリに左右されない。

設定に保存された効果音のパスだけは外部のファイルを読む。相対パスは `current_exe()` の親ディレクトリ基準で解決し、見つからなければ埋め込みの既定音へ倒す（`screenshot_sound::resolve_sound_path`）。**カレントディレクトリ基準でファイルを解決する処理を新たに足さないこと。**

## 設定の効果音は 3 つの状態を 1 つの値で表す

`screenshot.sound_file` は `Option<PathBuf>` 1 つで、次の 3 つを表す。

| 値 | 意味 | 設定画面の表示 |
|---|---|---|
| `Some("sound/SS.mp3")`（`settings::DEFAULT_SOUND_FILE`） | 内蔵の既定音 | 既定（内蔵） |
| `Some(それ以外のパス)` | ユーザーが選んだファイル | ファイル名 |
| `None` | 効果音を鳴らさない | なし（効果音を鳴らさない） |

- **内蔵の既定音は専用の値を持たず、既定値のパスが見つからないことで表す。** 既定値は旧版から相対パスのまま設定ファイルに保存されていて、変えると移行の前提が崩れるため。設定画面は既定値のパスと一致するかで「既定（内蔵）」を出し分ける（`ui::screenshot_tab` の `SoundChoice`）
- 既定音はファイルとして配布していないので、ファイル選択からは選び直せない。**設定画面の「既定に戻す」が `DEFAULT_SOUND_FILE` を書き戻すのが唯一の戻し方。** これが無かったときは、一度「効果音を鳴らさない」（旧「クリア」）にすると「設定を初期化...」以外で戻せなかった（Issue #201）
- `None` を内蔵音の意味に読み替えないこと。`None` が「鳴らさない」を表せる唯一の値で、`load_sound_data` はどのパスを渡しても鳴らせるデータを返す

## 効果音ファイルは別スレッドで読む

効果音ファイルの読み込みは、適用もテスト再生も UI スレッドで行わない（Issue #214）。ファイル全体を読んでデコードまで試すので、大きなファイルや遅いドライブでは適用やテスト再生の瞬間に描画が止まるため。スレッドの扱いは `docs/design/threads.md` の保存スレッドの節の後ろ。**読み込みが終わるまでの撮影は、直前の音か、それも無ければ内蔵音で鳴らす。** 無音にすると撮れたのかが分からないうえ、「鳴らさない」を選んだ状態と区別が付かない。「鳴らさない」への切り替え（`ScreenshotManager::clear_sound`）は読み込み中の要求も取り消すので、後から届いた結果で音が戻ることはない。適用は要求した時点で適用済みとして記録する（`last_sound_file`）。

### 読めなかったファイルを読み直す契機

**読めなかった（読めない・デコードできない）ファイルも適用済みのままにし、2 秒ごとの適用では読み直さない**（#507）。以前は読めないと分かった時点で記録を消していたので、ファイルがあるのに読めない状態（アクセス権が無い、ネットワークドライブが切れているなど）が続く間、2 秒ごとに読み込みスレッドを起こし、そのたびに `warn!` と `report_error` を出していた。読み直すのは次の 3 つだけ。

- **設定の効果音ファイルが変わったとき。** 2 秒ごとの適用の差分判定（`needs_reapply`）がそのまま拾う
- **設定ダイアログの「適用」「OK」を押したとき。** 設定を変えていなくても、最後の適用で読めていなければ読み直す（`retry_failed_sound_load` と `should_retry_sound_load`）。ファイルを直した利用者がすぐに読ませる手段はこれ。読めているファイルは押しても読み直さない。自動の読み直しの間隔は最初からやり直す
- **読めない（`SoundFileUnreadable`）ファイルを、間隔を延ばしながら自動で読み直す。** 最初は 30 秒後、失敗するたびに間隔を倍にし、5 分で止める（`next_sound_retry`、`CaptureCardViewer::sound_load_retry`）。起動直後にネットワークドライブがまだ繋がっていなかった場合などに、利用者が何もしなくても戻るようにするため（以前の 2 秒ごとの読み直しでは勝手に戻っていた）。時刻が来たかは 2 秒ごとの `apply_settings` が効果音の差分判定の前に見て（`start_due_sound_retry` / `is_sound_retry_due`）、来ていれば `last_sound_file` を空にして差分判定に拾わせる。読み直しを始めたら結果が届くまで次を予定しないので、遅いドライブで重ねて起こさない。**デコードできないファイルは自動では読み直さない。** 中身を差し替えない限り結果が変わらず、大きなファイルを数分ごとに読み直すだけになるため

テスト再生は契機にしない。テスト再生はドラフトのファイルを鳴らすだけで、適用済みの音に触らない決まり（Issue #204）なので、読めても適用済みの音を差し替えない。プリセットの切り替えも契機にしない（効果音はプリセットに入らない。`docs/design/presets.md`）。読めるようになるまでの撮影は内蔵音で鳴る。

**同じ理由が続く間は 1 度だけ報告する**（`CaptureCardViewer::sound_load_failure` と `should_report_sound_failure`、出力先を開けない失敗と同じ判定）。自動の読み直しや「適用」の押し直しで同じ理由で読めなかったときは、トーストを出さず「接続状態」タブの記録だけをその理由へ戻す。`ErrorCenter` の 60 秒ごとの再通知も、`report_error` を呼び直さないので起きない（`docs/design/error-reporting.md`）。読めたら記録を取り下げ（`errors.clear(ScreenshotSound)`。出力先の失敗が続いていればその理由へ戻す）、「鳴らさない」へ切り替えたときと、別のパスを適用したときは覚えた理由と自動の読み直しの予定を捨てる（`is_other_sound_path`。残すと新しいパスの最初の失敗が 30 秒からにならず、古い予定が新しいパスの読み込み中に来て重ねて読み直す）。出力先を開けるようになったときも、読み込めない失敗が残っていれば記録をその理由へ戻す（消すと、自動では読み直さないデコードできないファイルの失敗が「適用」までタブから消える）（選び直したら同じ理由でも改めて知らせる）。

## デコードできない効果音は撮影時に無音のまま

読めるが音声としてデコードできないファイル（拡張子だけ mp3 など）は、選んだ時点で検出して知らせる。`screenshot_sound::load_sound_data` が読み込みの直後に rodio でデコードを試し、失敗したら `ScreenshotError::SoundFileUndecodable` を添える。設定画面の「テスト再生」と「適用」（`apply_settings`）の両方がこれを `report_error(ErrorSource::ScreenshotSound, ..)` へ流し、トーストに出す。**撮影時の扱いは変えず、無音のまま**にする。内蔵音へ倒すと、ユーザーが選んだファイルと違う音が撮影のたびに鳴り、選び直す必要に気付きにくくなるため採らない（Issue #213）。見つからない・読めない場合に内蔵音へ倒すのとは扱いが違うので注意する。読み直す契機は読めないファイルと同じ（上の「読めなかったファイルを読み直す契機」）。
