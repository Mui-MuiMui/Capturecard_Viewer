# 手動テストチェックリスト

キャプチャーデバイスを接続した実機でのみ確認できる項目をまとめる。リリース前に一通り実施する。

自動テストの方針は `.claude/skills/testing-conventions/SKILL.md` を参照。

## 実施環境の記録

結果を残すときは以下も併記する。デバイス依存の不具合が多いため、環境が分からない結果は役に立たない。

- Windows のバージョン
- キャプチャーボードの製品名
- 選択したフォーマット / 解像度 / フレームレート
- オーディオ入力デバイス名

## 起動と表示

- [ ] 起動して数秒以内に映像が表示される
- [ ] 音声が出力される
- [ ] 映像と音声のズレが許容範囲内である
- [ ] ウィンドウのアイコンが既定の赤い四角ではなく、正しいアイコンになっている
- [ ] exe をショートカット経由で起動しても上記が同じ結果になる
- [ ] 作業ディレクトリが exe の場所と異なっても、アイコンが正しく表示され、効果音が鳴る
      （コマンドプロンプトで `cd C:\` してから exe を絶対パスで起動する）

## デバイス操作

- [ ] 右クリック > デバイス再接続 で映像と音声が復帰する
- [ ] キャプチャーボードの USB を抜き差ししたあと、デバイス再接続で復帰する
- [ ] 設定画面でビデオデバイスを切り替えると、その機器の映像に変わる
- [ ] 設定画面でオーディオ入力デバイスを切り替えると、その機器の音声に変わる
- [ ] 設定画面でサンプリングレートを 8000Hz にすると音質がこもり、48000Hz に戻すと元に戻る（デバイスが両方に対応している場合）
- [ ] サンプリングレートを変えたあと、音程と再生速度が変わらない（入力と出力で別の値が選ばれていないこと。ずれる場合は既知の不具合「入出力でレートが異なると音が崩れる」に該当する）
- [ ] デバイスが対応していないサンプリングレートを選んでも、音が止まらず最も近い値で鳴り続ける

## ウィンドウ操作

- [ ] ダブルクリックでフルスクリーンになり、もう一度で元に戻る
- [ ] フルスクリーンから戻ったとき、元のウィンドウサイズと位置が復元される
- [ ] 映像部分のドラッグでウィンドウが移動する
- [ ] 右クリック > 画面ドラッグ移動 をオフにすると、ドラッグで移動しなくなる
- [ ] 右クリック > 最前面表示 で他のウィンドウより前面に出る
- [ ] 右クリック > アスペクト比を維持 のオン / オフで表示が変わる
- [ ] ウィンドウを移動・リサイズして終了し、再起動すると位置とサイズが復元される
- [ ] ウィンドウを表示領域が潰れるまで小さくしても、落ちたり表示が乱れたりしない
- [ ] 最小化してから元に戻すと、映像が元どおり表示される

## 音量

- [ ] マウスホイールで音量が 10% ずつ変わる
- [ ] 音量 0% で無音になる
- [ ] 音量 200% まで上げられる
- [ ] 音量を変えて終了し、再起動しても保持されている
- [ ] 設定 > 音声パススルー のチェックを外すと音が止まる
- [ ] チェックを戻すとすぐに音が戻り、止めていた間の古い音が遅れて出てこない
- [ ] 音声パススルーを無効にしたまま終了し、再起動しても起動直後に音が出ない

## スクリーンショット

- [ ] ホットキー（既定 F5）で保存される
- [ ] 保存先が設定した フォルダになっている
- [ ] ファイル名が `年-月-日_時-分-秒-ミリ秒.jpg` になっている
- [ ] 効果音が鳴る
- [ ] 効果音の音量設定が反映される
- [ ] 設定画面の「テスト再生」で効果音が鳴る
- [ ] ホットキーを別のキーに変更すると、新しいキーで動作し、古いキーでは動作しない
- [ ] 他のアプリにフォーカスがある状態でもホットキーが効く

### ホットキー設定ダイアログ

- [ ] キャプチャ開始後に Ctrl や Shift を単独で押しても確定せず、「キー入力待機中...」のままになる
- [ ] キャプチャ開始後に Ctrl+Shift や Ctrl+Shift+Alt を押しても確定しない
- [ ] 上記の状態から続けて A を押すと `Ctrl+Shift+A` のように確定する
- [ ] 修飾キーなしで F5 を押すと `F5` が確定する
- [ ] 数字キー（例: `Ctrl+Shift+9`）を設定でき、そのキーでスクリーンショットが撮れる
- [ ] 確定したホットキーで OK を押すと、登録に失敗せずそのキーで動作する

## 設定画面

各ボタンの意味は `README.md` の「設定」を参照。設定画面での編集はドラフトとして扱われ、「適用」か「OK」を押すまで動作中のアプリにも設定ファイルにも影響しない。「適用」と「OK」の違いは画面を閉じるかどうかだけ。

- [ ] OK を押すと設定が反映され、再起動後も保持される
- [ ] 適用を押すと画面は閉じずに設定が反映され、そのまま終了・再起動しても保持される
- [ ] 適用を押さずにキャンセルを押すと、編集した内容が反映されない
- [ ] 適用を押したあとキャンセルを押しても、適用した内容は反映されたまま残る
- [ ] 設定ウィンドウを × で閉じると、編集した内容が反映されない（キャンセルと同じ）
- [ ] 設定ウィンドウを × で閉じたあと、もう一度開いてキャンセルしても、意図しない値に巻き戻らない
- [ ] 設定画面で値を編集しただけ（適用も OK も押さない）の状態でウィンドウを移動・リサイズし、キャンセルしてから終了・再起動しても、編集した値が保存されていない
- [ ] 設定画面を開いたままウィンドウを移動・リサイズしてから OK を押しても、ウィンドウの位置とサイズが巻き戻らない
- [ ] 設定画面でホットキーを変更しても、適用か OK を押すまでは古いホットキーが効く
- [ ] 効果音の音量スライダーを動かしてテスト再生すると、その音量で鳴る

### 設定ファイルの復帰

`%AppData%\capturecard_viewer\config\default-config.toml` をテキストエディタで編集して確認する。確認前に元のファイルを控えておくこと。

- [ ] 行を 1 つ削って起動すると、削った項目だけが既定値になり、他の設定は保持される
- [ ] `[ui]` のようにセクションごと削って起動しても、他のセクションの設定は保持される
- [ ] TOML として壊れた内容（`volume = ` のように値を欠いた行など）にして起動すると、既定値で起動し、同じフォルダに `default-config.toml.bak` が作られる
- [ ] 続けてもう一度壊して起動すると `default-config.toml.bak.1` が作られ、先の `.bak` の内容が残っている

## 現時点で既知の不具合により失敗する項目

以下は実装側の不具合が原因で落ちる。**対応する修正が入ったら、この節から外して上のチェックリストに統合する。**

- [ ] 設定 > チャンネル数 の変更が反映される
  → デバイスが対応する中で最も近い値へ寄せる実装になっているが、WASAPI はミックスフォーマットのチャンネル数しか報告しないため、実際にはデバイスの既定値しか選べない。選択肢をデバイスの能力から生成する作業がバックログにある
- [ ] 設定 > フォーマットで MJPEG や RGB24 を選ぶと、その形式で動作する
  → 現状は常に YUY2 で開かれる
- [ ] フルスクリーンのまま終了し、再起動するとウィンドウ表示で復元される
  → 現状は画面全体のサイズで復元される
- [ ] F12 をホットキーに設定できる
  → 他システムとの競合により登録できない（README の既知問題）

## 長時間動作

リリース前に一度は確認する。

- [ ] 1 時間以上連続で表示し続けても、映像が止まらない
- [ ] 同上の条件でメモリ使用量が増え続けない
- [ ] 同上の条件で音声にノイズやズレが蓄積しない
