# 手動テストチェックリスト

キャプチャーデバイスを接続した実機でのみ確認できる項目をまとめる。リリース前に一通り実施する。

自動テストの方針は `.claude/skills/testing-conventions/SKILL.md` を参照。

## 実施環境の記録

結果を残すときは以下も併記する。デバイス依存の不具合が多いため、環境が分からない結果は役に立たない。

- Windows のバージョン
- キャプチャーボードの製品名
- 選択したフォーマット / 解像度 / フレームレート
- オーディオ入力デバイス名

## 実機テストの映像源

キャプチャーボードの HDMI 入力には、`scripts/make-testpattern.sh` で作った動画を別の PC で全画面・ループ再生してつなぐ（ffmpeg が要る）。カラーバー・フレーム番号・1 秒ごとの白い四角と合図音・左右で違う正弦波が入っているので、色、フレーム落ち、録画の PTS、映像と音声のずれ、チャンネルの入れ替わりを数値で確かめられる。再生側はスリープと画面オフを無効にし、プレーヤーはブラウザーでなく VLC などを使う（広告や自動再生の切り替わりが切断に見える）。

## フェイクデバイスで代替できる項目

キャプチャーボードが手元に無くても、環境変数 `CAPTURECARD_VIEWER_FAKE_DEVICES=2` を指定して起動すると、アプリ内のフェイクデバイス（「Fake Camera 1」がカラーバー、「Fake Camera 2」が青のベタ塗り、音声は正弦波の入力と書き込みを捨てる出力）で動く。切断と接続失敗は `CAPTURECARD_VIEWER_FAKE_SCENARIO=disconnect:10`（10 秒ごとに映像が止まる）/ `fail:3`（開くのに 3 回失敗する）で起こせる。設定に実機のデバイス名が残っているとフェイクは「見つからない」で再試行し続けるので、設定画面でフェイクのデバイスを選ぶ（元に戻すときは実機を選び直す）。いつもの設定を変えたくなければ、`CAPTURECARD_VIEWER_CONFIG_DIR` に空のフォルダの絶対パスを指定して起動すると、設定とログがそのフォルダに置かれ、`%AppData%` の設定には触らない。仕組みは `docs/design/device-worker.md` の「フェイクデバイス（#142）」。

**フェイクで通しても、リリース前の実機での確認は省略しない。** Media Foundation / WASAPI そのものの挙動（接続にかかる時間、フォーマットの癖、USB の抜き差し、音が実際に聞こえるか）はフェイクでは再現できない。フェイクは実機を用意する前の予備確認と、機器を持っていない人が UI の変更を確かめる用途に使う。

| 節 | フェイクで確かめられること | 実機が要ること |
|---|---|---|
| 起動と表示 / 色空間と色レンジ / 映像調整 | 映像が出る、色空間・レンジ・映像調整を変えると次のフレームから色が変わる（カラーバーで見分けやすい） | 起動にかかる実時間、実機の信号での色の正しさ、音声が聞こえること |
| デバイス操作（デバイスの切り替え） | 2 台の切り替え（カラーバー ⇄ 青）、デバイス再接続 | USB の抜き差し |
| 稼働中の切断と自動復帰 | `disconnect:<秒>` で「映像信号がありません」→ 自動復帰、`fail:<回数>` で再試行 | USB を抜いたときの「デバイスが接続されていません」、音声デバイスが消えたときの復帰、マイクへ倒れないこと |
| 音量 / ミュート | OSD の表示、ホットキーでの増減（「接続状態」タブとアンダーランの数は動く） | 実際に聞こえる音量 |
| スクリーンショット | 保存・クリップボード・効果音（カラーバーとフレーム番号が写る） | — |
| 録画 | 開始・停止、録画中の印、統計 OSD の行、MP4 ができて再生できること、正弦波の音声トラックが入ること、`audio-error:<秒>` で音声を開き直しても音声の長さが映像と揃うこと、保存先に書けないとき・解像度を変えたときの通知、リプレイバッファでさかのぼった位置から始まること（焼き込んだフレーム番号で見る） | 1080p60 の長時間録画、ハードウェアエンコーダ、USB の抜き差し、録画中の FPS への影響、口の動きと音のずれ（冒頭と 30 分後）、音声デバイスの抜き差し、リプレイバッファを 5 分にしたときのメモリと継ぎ目 |
| 設定画面 / 接続状態タブ / プリセット | 選択肢の表示、接続状態の表示、リサンプル比と水位（出力が「Fake Audio Output 1」〈揃う〉でも「2」〈変換する〉でも出る）、音声バッファを 50 / 200ms に変えたときに水位が 100% 前後で落ち着くこと | 実機の対応形式の一覧、20ms でのアンダーラン（フェイクのスレッドは Windows のタイマーの粒度で起きるので、20ms では実機より途切れやすい） |
| ウィンドウ操作 / ホットキー / 言語 / フォント | デバイスに依存しないので、フェイクでもそのまま確認できる | — |
| 長時間動作 / 遅延 / CPU 使用率 | — | 実機で測る（フェイクの負荷は実機と違う） |

## 起動と表示

- [ ] 起動して 1〜2 秒以内に映像が表示される
      （固定の 2 秒待ちを廃止したので、以前より短くなっていること。実測では起動から接続完了まで 0.70〜0.87 秒、映像が出るまで 1.06〜1.12 秒）
- [ ] 音声が出力される
- [ ] 映像と音声のズレが許容範囲内である
- [ ] 1080p のソースで、黒い部分が灰色に浮かず、彩度が不自然に見えない
      （色空間「自動」では HD は BT.709、SD は BT.601 で変換している。解像度を 720x480 などの SD へ切り替えても同様に見えること。
      変換式そのものは、フェイクデバイスのカラーバーを流して RGB の期待値を確かめる自動テスト（`src/video/test_pattern.rs`）で担保している。
      ここで見るのは実機が送ってくる信号の色空間・レンジとの組み合わせ）

### 色空間と色レンジの設定

設定画面 > デバイス設定タブ > ビデオ設定 の「色空間」「色レンジ」で確認する。

- [ ] 色空間を「BT.601（SD）」にして「適用」を押すと、**デバイスが開き直らずに**（映像が途切れずに）色味が変わる
      （1080p のソースでは赤や肌色が変わって見える。無彩色のグレーでは変化しない）
- [ ] 色空間を「自動」に戻すと元の見え方に戻る
- [ ] 色レンジを「フル（0〜255）」にすると、黒い部分が灰色に浮き、白い部分が鈍くなる（リミテッドの信号を入れている場合。コントラストが落ちて見える）
      （逆にフルレンジの信号を入れている機種では、「リミテッド」のときに暗部が潰れ明るい部分が白飛びする。実際の信号に合うほうを選ぶのが正しい設定）
- [ ] 色レンジを「リミテッド（16〜235）」に戻すと元の見え方に戻る
- [ ] 上記を「適用」で反映したあと「キャンセル」で閉じても、反映済みの色味は戻らない（既存の適用／キャンセルの仕様どおり）
- [ ] ログ（`%AppData%\capturecard_viewer\logs`）に「色変換の設定を反映した」が、切り替えた回数ぶんだけ出ている
      （設定を変えていない間は 2 秒ごとに出ないこと）
- [ ] アプリを再起動すると、最後に選んだ色空間と色レンジが保たれている
- [ ] 設定ファイル（`default-config.toml`）の `[video]` に `color_space` / `color_range` が小文字の文字列で書かれている
- [ ] 設定ファイルの `color_space` を手で `"bt2020"` のような知らない値に書き換えて起動すると、**他の設定を失わずに**色空間だけが自動へ戻る
      （ログに「設定の色空間 ... を解釈できないので自動として扱う」が出る）

### 映像調整（明るさ / コントラスト / 彩度）

設定画面 > デバイス設定タブ > ビデオ設定 の「映像調整」で確認する。**色空間と色レンジを先に合わせてから**行う。

**各項目は「リセット」を押して 3 つとも 0 に戻した状態から始める。** 前の項目の値が残っていると期待する見え方にならない（例: 明るさ -50 のままコントラストを -100 にすると、一様にはなるが中間グレーではなく暗いグレーになる）。

- [ ] 明るさを +50 にして「適用」を押すと、**デバイスが開き直らずに**（映像が途切れずに）映像全体が明るくなる
- [ ] 明るさを -50 にすると暗くなる
- [ ] 明るさだけを 0 に戻し、コントラストを -100 にすると、映像が一様な中間グレー一色になる
- [ ] コントラストを +50 にすると明暗の差が強くなり、明るい部分が白飛びし始める
- [ ] コントラストを 0 に戻し、彩度を -100 にすると完全な白黒になる（色が一切残らないこと）
- [ ] 彩度を +50 にすると色が濃くなる
- [ ] 「リセット」を押して「適用」すると、3 つとも 0 に戻り、映像が調整前とまったく同じ見え方に戻る
- [ ] 調整した状態でスクリーンショットを撮ると、**保存された画にも調整が乗っている**（画面の見え方と一致する）
- [ ] 調整した状態でも、映像がカクついたりフレームレートが落ちたりしない
      （OSD の「FPS」と「デコード」の値が、無調整のときと変わらないこと）
- [ ] ログ（`%AppData%\capturecard_viewer\logs`）に「映像調整を反映した」が、切り替えた回数ぶんだけ出ている
      （設定を変えていない間は 2 秒ごとに出ないこと）
- [ ] アプリを再起動すると、最後に設定した映像調整の値が保たれている
- [ ] 設定ファイル（`default-config.toml`）の `[video]` に `brightness` / `contrast` / `saturation` が整数で書かれている
- [ ] 設定ファイルの `brightness` を手で `500` に書き換えて起動すると、**他の設定を失わずに** 100 へ丸められる
      （ログに「設定の映像調整（明るさ）500 は範囲外なので 100 として扱う」が出る）
- [ ] デバイスが YUY2 以外で映像を出している場合、ログに「デコーダへフォールバックする」が出て、色空間・色レンジ・映像調整のいずれも効かない
      （高速パスでしか係数を差し替えられないため。YUY2 で開ける機種しか手元に無い場合はこの項目を飛ばす）
- [ ] ウィンドウのアイコンが既定の赤い四角ではなく、正しいアイコンになっている
- [ ] exe をショートカット経由で起動しても上記が同じ結果になる
- [ ] 作業ディレクトリが exe の場所と異なっても、アイコンが正しく表示され、効果音が鳴る
      （コマンドプロンプトで `cd C:\` してから exe を絶対パスで起動する）

## デバイス操作

- [ ] 右クリック > デバイス再接続 で映像と音声が復帰する
- [ ] キャプチャーボードの USB を抜き差ししたあと、デバイス再接続で復帰する

### 稼働中の切断と自動復帰

自動再接続の既定は有効。確認の前に右クリックメニューで「デバイスの自動再接続」にチェックが入っていることを見る。

- [ ] 映像が出ている状態で USB を抜くと、3 秒ほどで最後の画が消え、「デバイスが接続されていません（再接続を試しています）」が出る
      （止まった画が残り続けないこと。抜いた瞬間ではなく数秒後に切り替わるのが正しい）
- [ ] USB を抜いたまま 15 秒待つと、設定画面の「接続状態」タブの映像の欄に「Windows 側にもデバイスが見えていない可能性があります…デバイスマネージャーで接続を確認してください」が出る
      （他に映像デバイスが無い環境では「1 台も見えていません」、Web カメラなどが残っている環境では「ほかのデバイスは見えています」と添えられる。
      トーストにも同じ案内が出るが、同じ文言は 60 秒に 1 度まで。ログに `デバイスの列挙（接続の失敗が続いている…）` の行が
      Media Foundation / DirectShow / 音声入力 / 音声出力の 4 行出ていること。挿し直して繋がったら案内は消える）
- [ ] そのまま USB を挿し直すと、操作しなくても映像と音声が戻る
      （再試行の間隔は最大 5 秒なので、挿してから 5〜10 秒ほど待つ。OS がデバイスを認識するまでの時間も含む。
      **音声は「デバイス再接続」を押さなくても戻ること。** 映像が戻った時点で音声にも再接続を要求するが、要求を出すことと繋がることは別で、
      音声デバイスが OS に現れるまで数回失敗しうる。**映像より数秒遅れて戻るのは正常。**
      判断は設定画面の「接続状態」タブで、音声が「再接続中」から実際のデバイス名の表示に変わったところで行う。
      映像が戻ってから 30 秒待っても音声が「再接続中」のままなら不合格）
- [ ] USB を抜いてから挿し直すまでの間、PC のマイクの音がスピーカーから流れない
      （この確認の前に、設定画面でオーディオ入力にキャプチャーボードを選んでおく。
      設定のデバイスが消えている間、Windows の既定の入力デバイスへ倒さないこと。
      設定画面の「接続状態」タブで、音声が「再接続中」になっていて、入力にマイクの名前が出ていないことでも確認できる）
- [ ] USB は挿したまま、入力機器の電源を切る（または HDMI ケーブルを抜く）と、3 秒ほどで「映像信号がありません」が出る
      （「デバイスが接続されていません」ではないこと。デバイスは掴めたままなので文言が変わる）
- [ ] 入力機器の電源を戻すと、操作しなくても映像が戻る
- [ ] 上の一連の操作でウィンドウが固まらない
      （ドラッグ、右クリックメニュー、ダブルクリックでのフルスクリーンがすべて反応すること）
- [ ] 右クリック > デバイスの自動再接続 のチェックを外してから USB を抜くと、表示は「映像信号がありません」に戻るが、挿し直しても自動では復帰しない
      （デバイス再接続を押せば復帰する。チェックの状態はアプリを再起動しても引き継がれる）
- [ ] 設定画面を開いたまま右クリックメニューで自動再接続を切り替え、設定画面の「適用」を押しても、切り替えた状態が巻き戻らない
- [ ] 一時的なコマ落ちで表示が消えない
      （通常の視聴を数分続けて、映像が勝手に「映像信号がありません」へ落ちないこと）
- [ ] キャプチャーボードを抜いた状態で起動し、あとから挿すと、操作しなくても映像と音声が出る
      （繋がるまで自動で再試行する。間隔は最大 5 秒なので、挿してから 5 秒ほど待つ）
- [ ] 上の再試行の間、ウィンドウが数秒固まらない
      （ドラッグで動かす、右クリックメニューを開く、ダブルクリックでフルスクリーンにする、がすべて反応すること。
      タスクマネージャーで「応答なし」にならないこと。
      デバイスを開く処理はワーカースレッドへ移したので、**1 回の試行で描画が飛ぶこともないこと**）
- [ ] 最小化したまま USB を抜き差ししても、元に戻したときには映像と音声が復帰している
      （最小化する前に映像が出ていること。最小化 → USB を抜く → 10 秒待つ → 挿し直す → 15 秒待つ → 元に戻す、の順。
      戻した瞬間はまだ「再接続を試しています」でも、そこから数秒で映像が出れば合格。
      **戻してから初めて再接続が始まるようでは不合格**。判断は最小化していた時間帯のログに
      `映像デバイスへの接続を試す（N 回目）` が並んでいるかで行う）
- [ ] 最小化中に自動再接続が走っても、元に戻したときに通知（トースト）が大量に流れない
      （失敗のたびにイベントが溜まるが、同じ理由は 60 秒間引かれる）
- [ ] 設定画面でデバイスを切り替えたときの反映が、従来どおり即座に行われる
      （再試行の待ち時間を挟まずに切り替わること）
- [ ] 設定画面を開いた直後、デバイスの選択肢が 1 秒以内に埋まる
      （デバイスの列挙もワーカースレッドへ移したため、開いた最初の一瞬だけ前回の一覧が出る。
      数秒経っても空のままなら不合格）
- [ ] 設定画面でビデオデバイスを切り替えると、その機器の映像に変わる
- [ ] 設定画面でビデオデバイスを切り替えても画面が固まらず、映っている映像も止まらない
      （対応形式の取得中はデバイス名の下にスピナーと「対応形式を取得中...」が出る。取得が終わると解像度とフレームレートの選択肢が増える）
- [ ] 設定画面でビデオデバイスを切り替えると、解像度とフレームレートも新しいデバイスが対応する値へ入れ替わる
      （切り替え前の値に最も近い組み合わせが選ばれる。新しいデバイスが同じ組み合わせに対応していれば、その値のまま残る。
      対応形式の取得が終わるまでは前のデバイスの値が出たままで、取得が終わった時点で入れ替わる。
      取得に失敗した場合は入れ替わらない）
- [ ] 上で入れ替わった解像度・フレームレートが、それぞれの選択肢の中に実在する
      （選択肢に無い値が選択中として表示されないこと。表示と実際にキャプチャーされる設定が食い違う原因になる）
- [ ] 起動直後に設定画面を開くと、保存済みデバイスの解像度とフレームレートが選べる
      （起動時に先読みしている。取得が終わる前に開いた場合はスピナーが出て、終わり次第選択肢が増える）
- [ ] 対応形式の取得に失敗すると理由が表示され、「再取得」ボタンで取り直せる
      （キャプチャーボードの USB を抜いた状態でデバイスを選ぶと再現できる。挿し直して「再取得」を押すと選択肢が出る）
- [ ] 設定画面でオーディオ入力デバイスを切り替えると、その機器の音声に変わる
- [ ] 設定画面でオーディオ出力デバイスだけを切り替えると、その機器から音が出る
      （出力先だけの変更では再接続が走らない不具合を直した。以前は切り替えても古い出力先で鳴り続けた）
- [ ] 設定画面でサンプリングレートを 8000Hz にすると音質がこもり、48000Hz に戻すと元に戻る（両方が選択肢に出る場合）
- [ ] サンプリングレートを変えたあと、音程と再生速度が変わらない
- [ ] サンプリングレートとチャンネル数の選択肢が、入力と出力の両方が対応する値だけになっている
      （設定 > 接続状態 に出る実際の値が、選んだ値と一致すること）
- [ ] 設定画面の「音声バッファ」スライダーを 20ms まで下げて「適用」すると、音声だけが開き直り遅延が減る
      （映像は途切れないこと。ログに「音声デバイスへの接続を試す ... バッファ: 20 ms」と出る。
      環境によってはこの長さでプチプチというノイズが出るが、それ自体は不具合ではない）
- [ ] 音声バッファを 200ms にすると、ノイズは減る代わりに映像より音が遅れて聞こえる
      （#308。50ms と聞き比べて、遅れが体感ではっきり増えること。以前は出力の開始が 50ms 固定の待ちで
      決まっていたので、200ms にしても最初に溜まるのは 50ms 前後で、遅れがほとんど変わらなかった。
      「接続状態」タブのバッファ水位が、開き直した直後から 100% 前後になっていることでも確認できる）
- [ ] 音声バッファを 20ms にして負荷をかけると、統計表示の「アンダーラン」の回数が増える
      （右クリックメニューの「情報表示」をオンにして左上の統計を出しておく。負荷は録画・エンコード・
      別アプリのビルドなど、CPU を継続的に使うもので掛ける。環境によっては 20ms でも増えないことがあるので、
      その場合は不合格にせず「増えなかった」と記録する）
- [ ] 同じ負荷のまま音声バッファを 200ms に戻して「適用」すると、回数が 0 から数え直され、以後ほとんど増えない
      （開き直しで 0 に戻ること自体も確認する）
- [ ] 音声を開けていない状態（オーディオ入力デバイスの USB を抜くなど）では「アンダーラン: -」と出る
      （0 回と出ないこと。開いていて一度も途切れていない状態と読み分けられなくなる）
- [ ] スライダーをドラッグしている間は音が途切れない（デバイスを開き直すのは「適用」か「OK」を押したとき）
- [ ] 音声バッファの値を変えて終了し、再起動しても保持されている
- [ ] `default-config.toml` の `[audio]` から `buffer_ms` の行を削除して起動しても、
      他の設定が消えず、これまでどおりの音（50ms 相当）で鳴る
- [ ] オーディオデバイスを切り替えた直後に、選択肢の取得中スピナーが出る。その間もウィンドウは固まらない
- [ ] チャンネル数の選択肢が 1 つしか無い場合、コンボボックスが操作できず理由が表示される
      （Windows の共有モードでは通常こうなる）
- [ ] 入出力で共通の値が無い組み合わせを選ぶと、両方の値が並び警告が出る
- [ ] 設定ファイルの `sample_rate` を選択肢に無い値（`11025` など）へ書き換えて起動すると、
      設定画面に警告と「実際に使われる値」が出る
- [ ] オーディオの対応設定の取得に失敗すると理由が表示され、「再取得」ボタンで取り直せる
      （入力デバイスの USB を抜いた状態で設定画面を開くと再現できる）
- [ ] 起動直後のログに、音声デバイスの対応設定の取得時間と、入出力を揃えられたかが残っている
- [ ] 入力 48000Hz・出力 44100Hz のように揃えられない組み合わせでも、音程と再生速度が正しい
      （Windows のサウンド設定で出力デバイスの既定の形式を 44100Hz に変えると再現できる。
      ログに「入出力の形が違うので変換する」と出て、それでも音が普通に鳴ること）
- [ ] 入力がステレオ・出力がモノラル（またはその逆）の組み合わせでも、左右が入れ替わったり片方が消えたりしない
- [ ] 左右で違う音（左だけ鳴るテスト音など）を入れて 30 分以上流しても、途中で左右が入れ替わらない。
      音声のバッファ長を最短（20ms）にしてアンダーランが出る状態でも同じ（#307。入出力が揃う組み合わせと、
      変換が入る組み合わせの両方）
- [ ] 入出力の形が揃う組み合わせと変換が入る組み合わせのどちらでも、10 分以上再生して音が途切れ続けたり
      遅延が増え続けたりしない
      （クロックドリフトをリングバッファの水位の数秒間の平均から補正する。#308 から揃う組み合わせも対象。
      水位が目標付近（デッドゾーン内）で安定していれば補正の必要が無いということなので、ログレベルを
      `debug` にしても「音声のリサンプル比を補正した」は出ないのが正常。目標から外れて補正が入ったときだけ
      数秒ごとに出る。開き直した直後の十数秒は、最初の水位の溜まり方で目標から少しずれるので数回出てよい。
      「水位が目標から大きく外れている」という `warn` は最大 30 秒間隔で間引かれるので、
      ずれ始めた直後に 1〜2 回出るだけなら正常。10 分間ずっと出続ける（水位が収束しない）場合は不具合）
- [ ] キャプチャーカードの音声を入出力の形が揃う組み合わせ（48kHz 2ch 同士など）で 30 分以上流しても、
      統計表示の「アンダーラン」が増え続けず、「接続状態」タブのバッファ水位が 200% 付近（満杯）に張り付かない
      （#308。公称レートが同じでも入出力は別の時計で動く。以前は揃う組み合わせに補正が無く、ずれの向きによって
      満杯に張り付いて遅延が延びるか、一定の間隔でアンダーランが出ていた。音声バッファは既定の 50ms で確かめる。
      30 分後のリサンプル比〈1.0000 からのずれ〉を記録する。機器の時計のずれの目安になる）
- [ ] 設定画面の「接続状態」タブの音声の欄に「リサンプル比」と「バッファ水位」が出る
      （数秒ごとに値が更新されること。#308 から入出力の形が揃う組み合わせでも出る。以前は「変換なし」と出ていた）
- [ ] 出力を「既定のデバイス」にして Windows のサウンド設定で既定の出力先を切り替えると、数秒で新しい機器から音が出る
      （切り替えてから最大で数秒〈確認間隔〉＋再接続の待ち時間ぶん待つ。設定画面の「接続状態」タブで、音声の出力に出る実デバイス名が新しい既定へ変わっていることでも確認できる。設定画面を開いていなくても追従すること）
- [ ] 入力は「既定のデバイス」を追いかけない（#304）
      （入力が未指定のときは音声を開かないため、入力を「既定のデバイス」のまま開いている状態が無い。`default-config.toml` の `[audio]` から `input_device_name` の行を削除して起動すると、起動時に列挙した先頭のデバイスが入る。設定画面のオーディオ入力デバイスの選択肢にも「デフォルト」が無い〈#153〉）
- [ ] 入力・出力のどちらかを明示的なデバイス名で固定している場合、Windows 側の既定を切り替えても固定した側は変わらない

      （ログを `debug` にすると `DirectShow の映像ストリームを開いた` と `最初のフレームが届いた` が出る）
- [ ] キャプチャーボードを 1 台目、OBS の仮想カメラを 2 台目として切り替えると、解像度とフレームレートの選択肢も切り替えた先のデバイスが対応する値へ入れ替わる（#78）。切り替えるたびに映像も切り替わる
      （OBS の仮想カメラの解像度と fps は OBS の「設定 > 映像」の出力解像度と FPS に従う）
- [ ] OBS の仮想カメラを映したまま OBS を終了し、また起動して仮想カメラを開始すると、操作しなくても映像が戻る
- [ ] OBS の仮想カメラを映したまま OBS 側で「仮想カメラ停止」を押すと、3 秒待たずに（1 秒以内に）最後の画が消え、「デバイスが接続されていません（再接続を試しています）」が出る（#229）

### CPU 使用率（再描画の間隔）

タスクマネージャーの「詳細」タブで `capturecard_viewer.exe` の CPU 列を見る。
**「1 コアあたり何 %」ではなく「全コアに対する何 %」で出るので、コア数が多い機械では小さな値になる。**
絶対値ではなく、下の項目どうしの差を見ること。

- [ ] 映像を表示している間の CPU が、v1.0.6 と比べて増えていない
- [ ] キャプチャーボードを外した（または未接続のデバイス名を設定した）状態にすると、CPU が映像表示中よりはっきり下がる
- [ ] 同じ状態で最小化すると、さらに下がってほぼ 0 になる
- [ ] 映像を表示したまま最小化しても CPU は残る（YUY2→RGB 変換はキャプチャー側で続くため。これは想定どおり）
- [ ] 映像が出ていない状態でも、プレースホルダーの文言の変化・トーストの消滅・自動再接続が従来どおり働く（体感で 1 秒以上遅れない）

### 遅延（最優先）

- [ ] 映像の遅延が v1.0.6 と変わらない
      入力機器にストップウォッチやマウスカーソルを出し、画面の反応が前より遅れていないことを見る。
      並べて比べる場合は、旧版と新版を同時に動かさず、1 つずつ確認する（同じデバイスを 2 つのプロセスからは開けない）

      上にカーソルを置くと理由が出る

### 移動のガード

- [ ] 右クリック > ウィンドウ > 画面ドラッグ移動 をオフにしてから 表示 >「タイトルバーを隠す」を入れると、
      画面ドラッグ移動が自動でオンに戻り、画面下部に
      「ウィンドウを動かすため、画面ドラッグ移動を有効にしました」が 2 秒ほど出る
- [ ] そのあと映像部分のドラッグでウィンドウが動く
- [ ] タイトルバーを隠している間は「ウィンドウ」>「画面ドラッグ移動」が灰色で押せない
- [ ] タイトルバーを戻すと「ウィンドウ」>「画面ドラッグ移動」を再びオフにできる
      （このとき、オンのまま勝手に固定されていないこと）
- [ ] `default-config.toml` を手で編集して `borderless = true` と `enable_drag_move = false`
      にして起動すると、`enable_drag_move` が true に直っていてウィンドウを動かせる
      （ログに「ドラッグ移動を有効にした」の警告が残る）

### リサイズ

- [ ] タイトルバーを隠した状態で、ウィンドウの左端・右端・上端・下端にカーソルを寄せると
      カーソルの形が変わり、ドラッグでその方向にサイズが変わる
- [ ] 四隅では斜めのカーソルになり、ドラッグで縦横が同時に変わる
- [ ] 端をドラッグしてもウィンドウが移動しない（サイズだけ変わる）
- [ ] 端から離れた映像の中央をドラッグすると、従来どおりウィンドウが移動する
- [ ] 右クリックメニューを開いた状態でメニューがウィンドウ端に重なっていても、
      メニューの項目を普通にクリックできる（リサイズが始まらない）
- [ ] 設定画面を開いている間はウィンドウ端でリサイズが始まらない
- [ ] リサイズしたサイズが終了・再起動後も復元される

### リセットと終了

- [ ] 右クリック > ウィンドウ > ウィンドウサイズをリセット で 1280x720 に戻る
- [ ] ウィンドウを掴めないほど小さくしてからでも、リセットで戻せる
- [ ] フルスクリーン中は「ウィンドウ」>「ウィンドウサイズをリセット」が灰色で押せない
- [ ] 右クリック > 終了 でアプリが閉じる
- [ ] タイトルバーを隠した状態で Alt+F4 を押すと閉じる
- [ ] 終了の直前に音量やウィンドウ位置を変えていても、再起動後にその値が残っている
      （デバウンスの待ち時間中に閉じても取りこぼさないこと）

## 音量

- [ ] マウスホイールで音量が 10% ずつ変わる
- [ ] 音量 0% で無音になる
- [ ] 音量 200% まで上げられる
- [ ] 音量を変えて終了し、再起動しても保持されている
- [ ] 音量 0% のまま終了し、再起動しても起動直後に音が出ない（一瞬も鳴らない）
- [ ] 設定 > 音声パススルー のチェックを外すと音が止まる
- [ ] チェックを戻すとすぐに音が戻り、止めていた間の古い音が遅れて出てこない
- [ ] 音声パススルーを無効にしたまま終了し、再起動しても起動直後に音が出ない

### 音量の表示（OSD）

- [ ] マウスホイールで音量を変えると、画面下部中央に「音量: N%」とバーが出る
- [ ] 表示される数字が、右クリックメニューの「音量: N%」と一致する
- [ ] ホイールを回し続けている間は表示が出たままで、手を止めてから 1.5 秒ほどで消える
- [ ] 100% の位置に目盛りが出ており、100% を超えるとその先のバーの色が変わる
- [ ] 音量 0% ではバーが空、200% ではバーが端まで埋まる
- [ ] 右クリックメニューの音量スライダーを動かしても同じ表示が出る
- [ ] 設定画面で音量に関わる操作をして「適用」か「OK」を押し、音量が変わった場合に表示が出る
      （音量を変えずに適用したときは出ないこと。2 秒ごとの設定の再適用で出っぱなしにならないこと）
- [ ] キャプチャーデバイスを抜いて「映像信号がありません」の状態にしてから音量を変えても、表示が 1.5 秒ほどで消える
      （映像が届かず再描画が止まる状態でも消えること。消えずに残る場合は再描画の予約が効いていない）
- [ ] 情報表示（統計オーバーレイ）をオンにしていても、音量の表示と重ならない
- [ ] 音量の表示が出ている間に、その真上あたりで映像をドラッグ・右クリックしても、ウィンドウ移動とコンテキストメニューが従来どおり働く
- [ ] フルスクリーンでも同じ位置に表示される

## ミュート

- [ ] 映像の上でミドルクリックすると音が止まり、もう一度押すと元の音量で戻る
- [ ] 映像が出ていない（「映像信号がありません」の）状態でもミドルクリックで切り替わる
- [ ] 右クリックメニューの「ミュート」のチェックが、いまの状態と一致している
- [ ] 右クリックメニューの「ミュート」を切り替えると音が止まる / 戻る
- [ ] 設定画面でホットキーの「ミュート切替」にキーを割り当てると、そのキーで切り替わる
- [ ] 他のアプリを操作している間もミュートのホットキーが効く
- [ ] ミュートしてから音量を 150% に変え、解除すると 150% で鳴る（0% には戻らない）
- [ ] ミュートしたまま終了し、再起動すると音が出ない（一瞬も鳴らない）。解除すると元の音量で鳴る
- [ ] ミュート解除の状態で終了し、再起動すると音が鳴る
- [ ] 設定画面を開いたままミュートを切り替えて「適用」を押しても、ミュートが巻き戻らない
- [ ] 音声パススルーのチェックを外した状態では、ミュートを解除しても音が出ない

### ミュートの表示（OSD）

- [ ] ミュートすると画面下部中央に「ミュート」と出て、1.5 秒ほどで消える
- [ ] 解除すると「ミュート解除（音量: N%）」と出る。N は右クリックメニューの数字と一致する
- [ ] フルスクリーンでも同じ位置に表示される

### ミュート中の音量操作

- [ ] ミュート中にマウスホイールを回すとミュートが解除され、その音量で鳴る
- [ ] ミュート中に音量のホットキー（音量を上げる / 下げる）を押してもミュートが解除される
- [ ] ミュート中に右クリックメニューのスライダーを動かしてもミュートは解除されず、音は出ないまま
- [ ] そのとき画面下部のバーが灰色で、文言が「音量: N%（ミュート中）」になっている

## スクリーンショット

- [ ] ホットキー（既定 F5）で保存される
- [ ] 撮影した瞬間に映像がカクつかない（動きの速い映像を出しながら撮ると分かりやすい）
- [ ] ホットキーを連打しても、押した回数だけファイルが保存される
- [ ] 撮影した直後にアプリを閉じても、最後の 1 枚が壊れずに保存されている
- [ ] 保存先が設定した フォルダになっている
- [ ] 保存形式が JPEG のとき、ファイル名が `年-月-日_時-分-秒-ミリ秒.jpg` になっている
- [ ] 設定 > 保存形式で PNG を選ぶと `年-月-日_時-分-秒-ミリ秒.png` で保存され、画像ビューアで開ける
- [ ] PNG のときは「JPEG 品質」のスライダーが操作できない
- [ ] JPEG の品質を 10 と 100 で撮り比べると、ファイルサイズがはっきり変わる
- [ ] 保存形式を PNG にして終了し、再起動しても PNG のままになっている
- [ ] 保存形式を追加する前の設定ファイル（`format` の行が無い状態）で起動しても JPEG で保存される
- [ ] 効果音が鳴る
- [ ] 効果音の音量設定が反映される
- [ ] 設定画面の「テスト再生」で効果音が鳴る
- [ ] 拡張子だけ mp3 のファイル（中身がテキストなど）を効果音に選ぶと、「テスト再生」と「適用」でトーストが出る。そのまま撮影すると無音になる
- [ ] ファイルを選び直した直後（「適用」を押す前）のテスト再生で、新しく選んだ音が鳴る。そのままキャンセルして撮影すると、元の音が鳴る
- [ ] 自分で選んだファイルを使っている状態で「既定に戻す」を押した直後（「適用」を押す前）のテスト再生で、内蔵の効果音が鳴る
- [ ] 大きな音声ファイル（数十 MB の wav など）を効果音に選んで「テスト再生」と「適用」を押しても、映像が止まらない。テスト再生は読み込みが終わったところで 1 回だけ鳴り、連打しても最後の 1 回だけが鳴る
- [ ] ホットキーを別のキーに変更すると、新しいキーで動作し、古いキーでは動作しない
- [ ] 他のアプリにフォーカスがある状態でもホットキーが効く
- [ ] 既定の設定で設定画面を開くと、効果音の欄が「既定（内蔵）」になっていて、「既定に戻す」は押せない（淡色表示）
- [ ] 設定画面で「効果音を鳴らさない」を押すと欄が「なし（効果音を鳴らさない）」になり、適用すると**再起動せずに**その場で無音になる（撮影自体は続けてできる）
- [ ] 効果音を鳴らさない状態から、もう一度ファイルを選んで適用すると、再起動せずに鳴るようになる
- [ ] 「効果音を鳴らさない」で適用 → 「既定に戻す」を押すと欄が「既定（内蔵）」に戻り、適用して撮影すると**内蔵の効果音**が鳴る（再起動は要らない）
- [ ] 自分で選んだファイルを使っている状態で「既定に戻す」→ 適用すると、撮影で内蔵の効果音が鳴る。終了・再起動しても「既定（内蔵）」のまま
- [ ] 自分で選んだファイルを使っているとき、欄のファイル名にマウスを重ねるとフルパスが出る

- [ ] 設定画面のスクリーンショット設定タブで、出力先の下の説明と保存形式の下の説明がどちらも 2 行で出て、2 行目が字下げされずに 1 行目と左端が揃っている（#225）

### 出力先

- [ ] 出力先を「クリップボードにコピー」にすると、「保存場所」と「保存形式」が操作できなくなる
- [ ] その状態でホットキーを押すと、保存フォルダにファイルが増えない
- [ ] 続けて別のアプリ（ペイント、Discord、Word など）に貼り付けると、撮った画がそのまま貼られる
- [ ] 貼り付けた画が全面透明・全面黒にならず、色も入れ替わっていない（赤が青になっていない）
- [ ] 撮影した直後にアプリを閉じても、そのあと別のアプリに貼り付けられる（終了してもクリップボードの内容が残る）
- [ ] 出力先を「両方」にすると、ファイルが保存され、かつ貼り付けもできる
- [ ] 出力先を「クリップボードにコピー」にして終了し、再起動しても設定が残っている
- [ ] 出力先を追加する前の設定ファイル（`destination` の行が無い状態）で起動すると、これまでどおりファイルに保存される
- [ ] `destination` に知らない値（例: `"printer"`）を書いて起動しても、他の設定が失われずファイル保存になる
- [ ] 出力先が「両方」で保存先を書き込めない場所にすると、トーストに保存の失敗理由と「（クリップボードへコピーした）」が出て、貼り付けはできる

## 録画

H.264 + AAC の MP4（第 1 段の映像 #281、第 2 段の音声 #282、第 3 段のリプレイバッファ #182）。仕組みは `docs/design/recording.md`。結果を残すときは、ログの「録画のファイルを作った」の行にあるエンコーダの名前と「ハードウェア」の値、停止時の「録画の音声:」の行（映像の時計に対する音声のずれ）も書く。

### 開始と停止

- [ ] 右クリックメニューの「録画を開始」で録画が始まり、映像の右上に赤い丸と経過時間が出る。経過時間は 1 秒ごとに進む
- [ ] 録画中は右クリックメニューの同じ位置が「録画を停止（00:00:12）」になり、押すと止まる。「録画を保存した: ファイル名」のトーストが出る
- [ ] 保存先（既定はビデオフォルダ）に `Recording_年-月-日_時-分-秒.mp4` ができている
- [ ] 同じ秒に 2 回録る（書式を秒の無いものにするなど）と、2 本目に `_2` が付く
- [ ] ホットキー（「録画の開始・停止」に割り当てたキー）でも開始・停止できる
- [ ] 最小化している間にホットキーを押しても録画は始まらず、元に戻したときにも始まらない
- [ ] フルスクリーンでも右上に録画中の印が出る。情報表示を切っていても出る
- [ ] 情報表示を入れると、録画中は「録画 00:00:12 / 書いた N / 捨てた N」と「エンコーダ 名前（ハードウェア / ソフトウェア）」の行が出る
- [ ] 「音声も録画する」がオンなら、その下に「音声: 無音 +N ms / 溢れ N 回」の行が出る（先頭を削っていれば「削除 -N ms」も入る）。音声デバイスが無い・抜いている間は無音の ms が増え続け、戻ると止まる。「音声も録画する」をオフにして録ると、この行は出ない
- [ ] 録画中にアプリを閉じても、それまでの録画が再生できるファイルとして残る（ログに「終了するので録画を止める」「録画を保存した」が出る）
- [ ] 映像が来ていない状態（デバイス未接続）で録画を開始して止めると、ファイルは作られず「映像が届かなかったので、ファイルを作りませんでした」のトーストが出る

### 再生できること（実機）

- [ ] 1080p60 を 10 分録り、Windows の「メディア プレーヤー」と VLC で最後まで再生できる。色がプレビューと同じに見える（黄・シアン・緑が鮮やかすぎたり沈んだりしない）
- [ ] 録画中も統計 OSD の FPS とフレーム間隔（ばらつき）が録画前と変わらない
- [ ] ログにエンコーダの名前が出ている（「録画のファイルを作った: …（…、エンコーダ: 名前、ハードウェア: はい / いいえ）」）
- [ ] ハードウェアエンコーダのある PC で「ハードウェアエンコーダを使う」を切ると、ログのハードウェアが「いいえ」になり、それでも録れる
- [ ] 停止時のログの「Vec の回収に失敗した回数」を記録する（多い場合は生データを渡す方式へ切り替える判断材料。`docs/design/recording.md`）
- [ ] 4GB を超える長さ（8Mbps なら 70 分ほど）を録っても再生できる（MF の MP4 シンクが 64bit のオフセットを書くかは未確認）

### 音声（第 2 段、実機）

- [ ] 録った MP4 を「メディア プレーヤー」と VLC で再生すると音が鳴る。プレーヤーの情報で音声が AAC 48kHz 2ch になっている
- [ ] 録画中に音量を 0 にする・ミュートにする・パススルーを切っても、録った MP4 には元の音量で音が入っている
- [ ] 口の動きや手拍子のように音と映像を見比べられる入力を 30 分以上録り、冒頭と 30 分後で音のずれを比べる。停止時のログの「録画の音声: … 映像の時計（PC）の N 秒に対して音声のサンプル数 ÷ レートは M 秒（差 X ms、Y ppm）」の差と、30 分後に見えるずれが合うこと（差と ppm を記録する。ドリフト補正を入れるかの判断材料。`docs/design/recording.md` の「ドリフト」）
- [ ] 録画中に音声デバイス（キャプチャーボードの USB、または音声入力）を抜いて挿し直す。抜いている間は無音になり、戻ったあとの音が映像とずれない（ログの「揃えるために足した無音」が抜いていた時間ほどになる）。録画は止まらない
- [ ] 音声デバイスが無い状態で録画しても、映像と同じ長さの無音の音声トラックが入り、再生できる
- [ ] 入力のサンプリングレートやチャンネル数が 48kHz 2ch と違うデバイス（44.1kHz、モノラルなど）でも、音の高さと速さが変わらずに録れる

### 失敗と通知（実機）

- [ ] 録画中に USB を抜いて同じ大きさで戻すと、録画は止まらず同じファイルへ続けて書かれる（途切れた間は直前の画のまま）
- [ ] 録画中に解像度を変える（設定画面で解像度を変えて適用する、入力機器の出力解像度を変える）と、録画が止まり「映像の大きさが … から … に変わったので録画を止めた」のトーストが出る。そこまでのファイルは再生できる
- [ ] 解像度を変えて止まったファイルの音声が映像と同じ長さ（プレーヤーで末尾まで再生して、音声が映像より先に終わらない。音声デバイスを外した状態で録っても同じ）（#314）
- [ ] 保存先を書き込めない場所（存在しないドライブ、読み取り専用のフォルダ）にして録画を始めると、始まらずに保存先と理由のトーストが出る
- [ ] 「録画」タブで保存先の欄を空にする（または `videos` のような相対パスにする）と、録画を始めたときに始まらず「ドライブ名 … から始まるフォルダではない」のトーストが出る。カレントディレクトリにファイルができない
- [ ] 保存先の空きが 500MB を切ったドライブでは始まらず、空き容量のトーストが出る。録画中に 500MB を切ると止まって同じトーストが出て、そこまでのファイルは再生できる
- [ ] ファイル名の書式に `%H:%M` のような使えない書式を入れると、設定画面の「録画」タブに注意書きが出る。そのまま録画すると既定の書式の名前で保存され、ログに理由が出る

### 設定

- [ ] 設定画面の「録画」タブで保存先・ファイル名の書式・ビットレート・ハードウェアエンコーダ・音声（録るか、ビットレート）を変えて「適用」すると、次の録画から効く（録画中に変えても、その録画は元の設定のまま）
- [ ] 「参照...」でフォルダを選ぶと保存先の欄に入る
- [ ] ファイル名の書式の下に、いまの時刻で作られる名前の例が出る
- [ ] ビットレートを 1000kbps と 20000kbps で録り比べると、ファイルの大きさがはっきり変わる
- [ ] 録画を入れる前の設定ファイル（`[recording]` が無い状態）で起動しても他の設定が失われず、録画は既定値で動く
- [ ] 「音声も録画する」を切ると、映像だけの MP4 になる（プレーヤーの情報に音声が無い）。音声のビットレートの欄は選べなくなる
- [ ] 音声のビットレートを 96kbps と 192kbps で録り比べると、同じ長さでファイルの大きさが変わる
- [ ] 第 1 段の版が書いた `[recording]`（音声の項目が無い）で起動すると、音声を 160kbps で録る設定になり、他の項目は保たれる
- [ ] プリセットを切り替えても録画の設定は変わらない

### リプレイバッファ（第 3 段、#182）

「録画」タブの「リプレイバッファ（さかのぼり録画）」。結果を残すときは、ログの「リプレイバッファのエンコーダを作った」の行（エンコーダの名前とハードウェアかどうか）と、停止時の「録画を保存した: …、さかのぼり N 秒（リングの映像 N 秒、捨てた GOP N 回）」も書く。

フェイク（`CAPTURECARD_VIEWER_FAKE_DEVICES=1`）で確かめられるもの:

- [ ] 「録画の開始時に、直前の映像と音声を含める」をオンにして「適用」し、20 秒待ってから録画を 5 秒して止める。できた MP4 が約 25 秒で、最初から再生できる。左上に焼き込まれたフレーム番号で、先頭が録画を始める約 20 秒前（オンにした直後）から始まっていることを確かめる
- [ ] さかのぼる長さを 10 秒にして 30 秒待ってから 5 秒録ると、MP4 は約 13〜15 秒になる（さかのぼるのは 8〜10 秒。2 秒ごとのキーフレームに合わせるため最大 2 秒短くなる）
- [ ] 録画中は情報表示の録画の行に「/ さかのぼり N 秒」が付く。オンなだけで録画していないときは、情報表示にも「接続状態」タブにも何も出ない
- [ ] 録画中にリプレイバッファをオフにして「適用」しても、その録画は止まらずに最後まで保存される。止めたあとで次に録画すると、さかのぼらない
- [ ] オフで録画している間にオンにすると、その録画はさかのぼらずに保存され、止めたところから溜め始める（次の録画でさかのぼる）
- [ ] オンにしたまま、映像のビットレートや音声の設定を変えて「適用」すると、溜めた分を捨てて溜め直す（ログに「リプレイバッファを止めた」「リプレイバッファを始めた」が出る）。さかのぼる長さだけを変えたときは溜め直さない
- [ ] オンのまま録画中にアプリを閉じても、それまでの録画（さかのぼった分を含む）が再生できるファイルとして残る

実機で確かめること:

- [ ] 30fps の機器でオンにして 30 秒以上待ち、USB を抜いて数秒後に戻してから録画すると、抜く前の分もさかのぼって入っている。抜いている間と戻したときに、ログに「リプレイバッファを止めた」「リプレイバッファを始めた」が出ない（#306）
- [ ] さかのぼる長さを 5 分にして 5 分以上待ち、タスク マネージャーでアプリのメモリ使用量が 8Mbps のときおよそ 300MB 増えたところで頭打ちになる（増え続けない）
- [ ] 1080p60 の実機で、さかのぼった部分からライブの部分への継ぎ目（録画を始めた瞬間）で、映像も音声も途切れず、音と映像がずれない
- [ ] オフのときの CPU / GPU 使用率が、リプレイバッファを入れる前の版（録画していない状態）と変わらない。オンにすると、録画していなくてもエンコーダの分だけ上がる
- [ ] ハードウェアエンコーダのある PC で、ログの「リプレイバッファのエンコーダを作った」がハードウェアの名前（Intel / NVIDIA / AMD）になり、録ったファイルが再生できる。`cargo test -- --ignored hardware_h264_encoder_emits_keyframes_every_two_seconds` も通る（非同期型の MFT を通すテスト）
- [ ] ハードウェアエンコーダを使えない場合でも、ソフトウェアのエンコーダで溜め、録画できる。どちらも作れない場合は「リプレイバッファ（さかのぼり録画）を使えない」のトーストが出て、録画はさかのぼらずに行われる
- [ ] オンで録画中に解像度を変えると、①と同じく録画が止まり、そこまでのファイルは再生できる。止まったあともリプレイバッファは新しい大きさで溜め直している
- [ ] 設定ファイルの `replay_seconds` に範囲外の値（`1`、`1000`）を書いて起動すると、5 秒 / 300 秒として扱われ、他の設定は失われない

## 設定画面

各ボタンの意味は `README.md` の「設定」を参照。設定画面での編集はドラフトとして扱われ、「適用」か「OK」を押すまで動作中のアプリにも設定ファイルにも影響しない。「適用」と「OK」の違いは画面を閉じるかどうかだけ。

唯一の例外は効果音の「テスト再生」で、適用前でも編集中の効果音を編集中の音量で鳴らす。撮影で鳴る効果音は適用するまで差し替わらない。

- [ ] OK を押すと設定が反映され、再起動後も保持される
- [ ] 適用を押すと画面は閉じずに設定が反映され、そのまま終了・再起動しても保持される
- [ ] 適用を押さずにキャンセルを押すと、編集した内容が反映されない
- [ ] 適用を押したあとキャンセルを押しても、適用した内容は反映されたまま残る
- [ ] 設定ウィンドウを × で閉じると、編集した内容が反映されない（キャンセルと同じ）
- [ ] 設定ウィンドウを × で閉じたあと、もう一度開いてキャンセルしても、意図しない値に巻き戻らない
- [ ] 設定画面で値を編集しただけ（適用も OK も押さない）の状態でウィンドウを移動・リサイズし、キャンセルしてから終了・再起動しても、編集した値が保存されていない
- [ ] 設定画面を開いたままウィンドウを移動・リサイズしてから OK を押しても、ウィンドウの位置とサイズが巻き戻らない
- [ ] 設定画面でホットキーを変更しても、適用か OK を押すまでは古いホットキーが効く
- [ ] 効果音の音量スライダーを動かしてテスト再生すると、適用前でもその音量で鳴る
- [ ] 設定画面を開いたまま映像上でホイール操作をして音量を変え、設定画面で適用か OK を押しても、音量が巻き戻らない

### 警告文と接続状態の表示が読める（ライト / ダーク）

ウィンドウのテーマは Windows の設定に追従する。**ライトとダークの両方で確認する。** 切り替えは Windows の「設定 > 個人用設定 > 色 > アプリ モードを選ぶ」で行い、切り替えたらアプリを再起動する。

注意書きは彩度の高い文字色ではなく、薄い背景の枠と先頭の記号（注意は `⚠`、失敗は `×`、正常は `●`）で示している。

- [ ] ライトテーマで、設定 > デバイス設定 の音声パススルーのチェックを外したときの注意書きが読める
- [ ] ダークテーマで同じ注意書きが読める
- [ ] 設定 > その他 > 設定を初期化... を押したときの確認文が、両方のテーマで読める
- [ ] 同じキーを 2 つのアクションへ割り当てたときの注意書きと、一覧に出る `⚠` 付きのキー表記が、両方のテーマで読める
- [ ] 設定 > 接続状態 の「接続中」「未接続」が、両方のテーマで読める
- [ ] 画面をモノクロで見ても（または色を見分けられない前提で）、記号と文言だけで接続中・再接続中・未接続を区別できる

### 接続状態タブ

設定 > 接続状態 で確認する。表示だけのタブなので、「適用」「OK」「キャンセル」で内容は変わらない。

- [ ] 映像と音声のどちらも「● 接続中」と出て、実際に開いたデバイス名が出る
- [ ] 映像に、実際に開いた解像度とフォーマット（例: `1920x1080 YUYV`）と、要求フレームレートが出る
      （要求フレームレートは設定した値。デバイスが確定させた実 fps は nokhwa から取れないため出していない）
- [ ] 音声に、入力と出力それぞれのデバイス名・サンプリングレート・チャンネル数が出る
      （設定画面で選んだ値と食い違うことがある。デバイスが対応する中で最も近い値へ寄せるため）
- [ ] 音声に「アンダーラン: n 回」が出て、統計表示（情報表示）に出ている数と一致する
- [ ] どちらも「直近のエラー: なし」と出る
- [ ] キャプチャーボードの USB を抜くと、映像が「⚠ 未接続（再接続を試しています）」に変わり、連続失敗回数が増えていく
- [ ] 同じ状態で直近のエラーと発生時刻が出る
- [ ] USB を挿し直して繋がると、直近のエラーの表示が「なし」に戻る
- [ ] 設定画面を開いたままでも映像がカクつかない（毎フレームの取得が重くなっていないこと）

### プリセット

設定 > その他 の「プリセット」節と、右クリックメニューの「プリセット」で確認する。**解像度や FPS が違う 2 つの組み合わせを用意しておくこと**（例: 1280x720 60fps と 1920x1080 30fps）。

作成と一覧

- [ ] プリセットが 1 件も無いとき、その他タブに「プリセットはまだありません。」が出ており、右クリックメニューに「プリセット」が**無い**
- [ ] デバイス設定タブで 720p60 にしてから、その他タブで名前に「低遅延優先」と入れて「保存」を押すと、一覧に 1 行増え「現在: 低遅延優先」になる
- [ ] 名前を入れずに「保存」を押すと「プリセット名を入力してください」が出て、一覧は増えない
- [ ] 空白だけの名前でも同じく弾かれる
- [ ] 既にある名前で「保存」を押すと「同じ名前のプリセットが既にあります」が出て、**入力欄の文字が消えない**
- [ ] 名前を入れて Enter を押しても保存できる
- [ ] デバイス設定タブで 1080p30 にしてから「画質優先」で保存すると、一覧が 2 行になる

切り替え（右クリックメニュー）

- [ ] 「適用」または「OK」を押したあと、右クリックメニューに「プリセット  ⏵」が現れ、開くと 2 つとも並んでいる
- [ ] 現在の設定と一致するプリセットにチェックが付いている
- [ ] もう一方を選ぶとメニューが閉じ、画面下部に「プリセット: 名前」が 1.5 秒ほど出て消える
- [ ] 選んだあと、デバイスが開き直り、映像の解像度と FPS が切り替わる（情報表示をオンにして確認する）
- [ ] 既に選ばれているプリセットを選び直しても、**映像が途切れない**（デバイスの開き直しが起きない）
- [ ] 切り替えたあとアプリを終了して起動し直すと、切り替えた側の設定で立ち上がる
- [ ] 切り替えたあとにホイールで音量を変えても、保存先やホットキーは変わらない
- [ ] 右クリックメニューの「デバイスの自動再接続」を切ってからプリセットを切り替えても、**オフのまま戻らない**

管理 UI（ドラフト方式）

- [ ] 一覧の「読み込む」を押すと「プリセット「...」を読み込みました。...」が出て、デバイス設定タブの表示がその内容に変わる
- [ ] 「読み込む」を押しただけでは動作中の映像が変わらない
- [ ] 「読み込む」のあと「キャンセル」を押すと、何も反映されない
- [ ] プリセットを読み込んだあと解像度を手で変えると、「現在:」が「名前（変更あり）」になる
- [ ] その状態で「適用」を押すと、右クリックメニューのチェックがどのプリセットにも付かなくなる
- [ ] 一覧の「上書き保存」を押すと、そのプリセットが編集中の値に置き換わり、「現在:」がそのプリセット名になる
- [ ] 一覧の「削除」を押すと一覧から消え、「キャンセル」を押すと戻る
- [ ] 削除して「適用」すると、右クリックメニューの「プリセット」からも消える。最後の 1 件を消すと「プリセット」の項目ごと消える
- [ ] 設定画面を × で閉じて開き直すと、名前の入力欄が空になっている

書き出し・読み込み・初期化との関係

- [ ] プリセットがある状態で設定を書き出すと、ファイルに `[[presets]]` が含まれている
- [ ] プリセットを消してから、そのファイルを読み込んで「適用」すると、プリセットが戻る
- [ ] 「設定を初期化...」→「初期化する」→「適用」を行っても、**プリセットの一覧が消えない**
      （初期化の対象は従来どおり。ビデオ・オーディオ設定に加えてスクリーンショットの設定とホットキーも既定値へ戻り、
      プリセットの一覧とウィンドウの位置・サイズは残る）

### その他タブ（設定の書き出し・読み込み・初期化）

設定 > その他 で確認する。書き出しと読み込みのファイルダイアログはモーダルなので、**出している間は映像の更新が止まる。これは仕様。**

書き出し

- [ ] 「設定を書き出す...」を押すと保存ダイアログが出て、ファイル名の既定が `capturecard_viewer-settings-<今日の日付>.toml` になっている
- [ ] 保存すると、そのパスへ書き出した旨がタブ内に 1 行出る
- [ ] 書き出したファイルをテキストエディタで開くと、`%AppData%` の設定ファイルと同じ形式で現在の設定が入っている
- [ ] 保存ダイアログをキャンセルすると、何も起きずメッセージも出ない
- [ ] 設定画面で値を編集し、**適用せずに**書き出すと、編集前（動作中）の値が書き出される
- [ ] 書き込めない場所（例: `C:\Windows\System32`）へ保存しようとすると、「設定ファイルを読み書きできません: ...」がタブ内と画面下部の両方に出る

読み込み

- [ ] 別の設定で書き出したファイルを「設定を読み込む...」で読むと、デバイス設定タブとスクリーンショット設定タブの表示がその内容に変わる
- [ ] 読み込んだ直後にタブ内へ「... を読み込みました。「適用」または「OK」で反映します」が出る
- [ ] 読み込んだだけでは動作中のアプリが変わらない（映像デバイスが切り替わらない、ホットキーも古いまま）
- [ ] 読み込んだあと「キャンセル」を押すと、何も反映されない
- [ ] 読み込んだあと「適用」を押すと反映され、タブ内のメッセージが消える
- [ ] ウィンドウを動かしてサイズを変えてから、別の位置・サイズで書き出したファイルを読み込んで適用しても、**ウィンドウの位置とサイズが変わらない**
- [ ] 右クリックメニューの「最前面表示」「画面ドラッグ移動」「情報表示」「ミュート」「ボーダーレス表示」の状態が、読み込みと適用で変わらない
- [ ] 右クリックメニューの「デバイスの自動再接続」を切ってから、オンの状態で書き出したファイルを読み込んで適用すると、オンに戻る
- [ ] TOML として壊れたファイル（拡張子だけ `.toml` にしたテキストなど）を読むと、「設定ファイルを読み書きできません: ...」が出て、**編集中の内容が一切変わらない**
- [ ] `format = "webp"` のように解釈できない値を混ぜたファイルを読むと、その項目だけが既定値になり、残りは読み込まれる
- [ ] ファイル選択ダイアログをキャンセルすると、何も起きずメッセージも出ない

初期化

- [ ] 「設定を初期化...」を押すと確認の 1 行と「初期化する」「やめる」が出る
- [ ] 「やめる」を押すと元のボタンに戻り、設定は変わらない
- [ ] 「初期化する」を押すと編集中の設定が既定値になり（読み込みと同じ対象。ウィンドウの位置とサイズは戻らない）、タブ内に「初期値に戻しました。...」が出る
- [ ] そのまま「キャンセル」を押すと、動作中の設定は変わらない
- [ ] 「適用」を押すと既定値が反映される（ホットキーが F5 だけになる、保存先がデスクトップに戻る）
- [ ] 初期化して適用しても、**ウィンドウの位置とサイズが変わらない**
- [ ] 右クリックメニューの「デバイスの自動再接続」を切ってから初期化して適用すると、既定のオンに戻る
- [ ] 内蔵マイクのあるノート PC で、キャプチャーボードの音を流している状態から初期化して適用すると、**内蔵マイクの音がスピーカーから出ない**（#304）。音声は止まり、「音声デバイスに接続できません: オーディオ入力デバイスが選ばれていません。…」が画面下部と「接続状態」タブに 1 度出る。ログに「入力デバイスが未設定なので音声を開かない」が出て、「音声デバイスへの接続を試す - 入力: None」は出ない
- [ ] 続けてデバイス設定タブでオーディオ入力デバイスを選び直して適用すると、その入力の音が出る
- [ ] `[audio]` に `input_device_name` の無いファイルを読み込んで適用しても、同じく内蔵マイクは開かない
- [ ] 映像が映っている状態から初期化して適用すると、**映像が止まり**、映像エリアに「デバイスが接続されていません」と「映像デバイスに接続できません: 映像デバイスが選ばれていません。…」が出る（#334）。同じ文言が画面下部と「接続状態」タブにも 1 度出て、「接続状態」タブの映像は「未接続」になる。ログに「映像デバイスが未設定なので映像を開かない」が出る
- [ ] 続けてデバイス設定タブで映像デバイスを選び直して適用すると、映像が戻り、エラーが消える
- [ ] `[video]` に `device_name` の無いファイルを読み込んで適用しても、同じく映像が止まって同じ文言が出る
- [ ] 設定画面を × で閉じて開き直すと、確認待ちの状態もタブ内のメッセージも残っていない

### エラーの通知（トースト）

存在しないデバイス名を設定ファイルに書いて起動すると再現できる。確認前に元のファイルを控えておくこと。

- [ ] `[video]` の `device_name` を実在しない名前に書き換えて起動すると、画面下部中央に「映像デバイスに接続できません: ...」が数秒出て消える
- [ ] 同じ状態で、映像のプレースホルダーの 2 行目に同じ理由が出ている
- [ ] そのまま放置しても、トーストが数秒おきに出続けない（同じ内容は 60 秒間引かれる）
- [ ] `[audio]` の `input_device_name` も実在しない名前にすると、音声側の理由も出る
- [ ] 正しいデバイス名に戻して起動すると、トーストもプレースホルダーの 2 行目も出ない
- [ ] 映像が出ている状態で入力信号だけを落とすと「映像信号がありません」だけが出て、接続エラーの 1 行は添えられない
- [ ] スクリーンショットの保存先を書き込めない場所（例: `C:\Windows\System32`）にしてホットキーを押すと、「スクリーンショットを出力できません: ...」が出る
- [ ] 映像が出ていない状態でホットキーを押すと、「スクリーンショットを出力できません: 表示中の映像がありません」が出る

### フェイクデバイスの帯（#252）

環境変数 `CAPTURECARD_VIEWER_FAKE_DEVICES=1` と、`CAPTURECARD_VIEWER_CONFIG_DIR` に作業用フォルダの絶対パスを指定して起動する（`%AppData%` の設定に触らない）。実機のデバイス名が残った設定で確かめる項目（2 つ目）は、先にいつもの `%AppData%\capturecard_viewer\config\default-config.toml` をそのフォルダへコピーしておく。

- [ ] 映像の上端中央に「⚠ テスト用のフェイクデバイスで動いています（環境変数 CAPTURECARD_VIEWER_FAKE_DEVICES）」の帯が出て、時間が経っても消えない
- [ ] 設定ファイルに実機のデバイス名が残っている状態で起動し、画面下部に「映像デバイスに接続できません: ...」のトーストが出ても、帯は上端に出たまま
- [ ] 同じ状態で、起動直後（1〜3 秒）から映像エリアの中央に「デバイスが接続されていません（再接続を試しています）」と 2 行目の理由が出る。10 秒経っても出たまま。その中央の文言の上でもドラッグでウィンドウが動き、右クリックでメニューが出る。フルスクリーンでも同じ文言が中央に出る（#274）
- [ ] 右クリックメニューで統計オーバーレイを出すと、帯が統計の枠の下へずれて重ならない。ウィンドウを狭くしても重ならない
- [ ] ウィンドウ表示で帯の上を右クリックすると右クリックメニューが出て、ドラッグするとウィンドウが動く（映像の上と同じ）
- [ ] フルスクリーンでも帯が出る。帯の上を右クリックすると右クリックメニューが出る
- [ ] 設定→「接続状態」タブの先頭にも同じ文言が出る
- [ ] 環境変数を外して起動すると、帯もタブの注意書きも出ない
- [ ] 言語を English にすると、帯が英語（「Running with fake test devices ...」）になる

### 映像の上の表示と設定ダイアログの重なり（#284）

環境変数 `CAPTURECARD_VIEWER_FAKE_DEVICES=1` と、`CAPTURECARD_VIEWER_CONFIG_DIR` に作業用フォルダの絶対パスを指定して起動する（`%AppData%` の設定に触らない）。録画の開始・停止にホットキーを割り当てておく。

- [ ] 右クリックメニューの「情報表示」をオンにし、録画を始めて、統計・帯・右上の録画中の印を出す。その状態で「詳細設定...」を開くと、ダイアログが重なった部分では統計・帯が**ダイアログの下に隠れ**、ダイアログの文字が読める
- [ ] ダイアログを右上へドラッグして録画中の印に重ねると、印もダイアログの下に隠れる
- [ ] ダイアログを開いたまま、ホットキーで録画を止めて始め直す（印が出直す）。印はダイアログの下に隠れたまま
- [ ] ダイアログを閉じると、統計・帯・録画中の印が元どおり見える。帯と録画中の印は中身の幅だけで、横いっぱいに広がらない
- [ ] 統計の枠の上を右クリックすると右クリックメニューが出て、ドラッグするとウィンドウが動く（映像の上と同じ）
- [ ] ダイアログを開いたままプリセットを切り替える（ダイアログの外の右クリックメニューから）と、画面下部の「プリセット: 名前」のトーストはダイアログより**上**に出る

### 設定ファイルの復帰

`%AppData%\capturecard_viewer\config\default-config.toml` をテキストエディタで編集して確認する。確認前に元のファイルを控えておくこと。

- [ ] 行を 1 つ削って起動すると、削った項目だけが既定値になり、他の設定は保持される
- [ ] `[ui]` のようにセクションごと削って起動しても、他のセクションの設定は保持される
- [ ] TOML として壊れた内容（`volume = ` のように値を欠いた行など）にして起動すると、既定値で起動し、同じフォルダに `default-config.toml.bak` が作られる
- [ ] 続けてもう一度壊して起動すると `default-config.toml.bak.1` が作られ、先の `.bak` の内容が残っている
- [ ] `[ui]` の `volume` を `1000.0` に書き換えて起動すると、音量が 200% として扱われる
      （右クリックメニューの表示も音量 OSD も 200%。ログに範囲外である旨の警告が残る）

## 言語

設定画面の「その他」タブの「言語（Language）」で切り替える。OS の表示言語は Windows の 設定 > 時刻と言語 > 言語と地域 > Windows の表示言語 で変える（反映にはサインアウトが要る）。

- [ ] 言語の項目が無い設定ファイル（1.1.0 以前）で日本語の Windows から起動すると、これまでどおり日本語で出る。設定画面の言語は「自動（OS の言語に合わせる）」になっている
- [ ] 言語を「English」にして「適用」を押すと、再起動せずに設定画面の見出し・タブ名・ボタン・説明文が英語になる。**設定画面の位置と大きさは変わらない**（初期位置へ飛ばない）
- [ ] 続けて右クリックメニューを開くと、項目名とサブメニュー名（「View  ⏵」など）が英語になっている
- [ ] ホイールで音量を変える / ミュートを切り替える / ダブルクリックでフルスクリーンを切り替える / 右クリックメニューからプリセットを切り替えると、OSD（「Volume: 80%」「Mute」「Fullscreen ON」「Preset: 名前」）が英語で出る
- [ ] 「情報表示」をオンにすると統計が英語（「Jitter」「Decode」「Last frame」）で出る
- [ ] 存在しないデバイス名を設定して起動する（「エラーの通知（トースト）」の手順）と、トーストとプレースホルダーが英語（「Cannot connect to the video device: Video device '...' not found」「No device connected (trying to reconnect)」）で出る
- [ ] ホットキー入力ダイアログ（ホットキータブの「Set...」）の見出しと説明も英語になっている
- [ ] 英語のまま「OK」で閉じて再起動すると、英語で起動する。設定ファイルの `[ui]` に `language = "en"` がある
- [ ] 言語を「日本語」に戻して「適用」を押すと、再起動せずに日本語へ戻る
- [ ] 言語を「English」に変えて「適用」を押さずに「キャンセル」で閉じると、日本語のまま
- [ ] OS の表示言語が日本語以外（英語など）の Windows で、言語を「自動」にして起動すると英語で出る。「日本語」を選べば日本語になる
- [ ] 設定ファイルの `language` に知らない値（例: `"fr"`）を書いて起動しても、他の設定が失われず「自動」として扱われる
- [ ] 英語表示でもログ（`%AppData%\capturecard_viewer\logs`）の文言は日本語のまま

## 更新

起動時の更新の確認と通知ダイアログ、「更新する」からの適用（Issue #240）。適用の項目は下の「更新の適用」にまとめた。
通知を出すには、比較に使う「いまの版」を環境変数で最新の Release より古くして起動する（ビルドし直さなくてよい。`docs/design/update.md` の「試すための環境変数」）。確認前に設定ファイルを控えておくこと。

```
set CAPTURECARD_VIEWER_UPDATE_CURRENT_VERSION=1.0.0
"C:\path\to\capturecard_viewer.exe"
```

下の「版を差し替えて起動」はこの指定をしたうえでの起動、「通常の起動」は `set CAPTURECARD_VIEWER_UPDATE_CURRENT_VERSION=` で消してからの起動を指す。

- [ ] 版を差し替えて起動すると、ログ（`%AppData%\capturecard_viewer\logs`）に「更新の確認のテスト用のオーバーライドが有効」の WARN が出る。通常の起動では出ない

- [ ] 版を差し替えて起動すると、映像の上に「新しいバージョンがあります」のダイアログが出て、「新しいバージョン vX.Y.Z があります（いまは v1.0.0）」の 1 行と、「リリースノートを見る」「更新する」「後で」「このバージョンは通知しない」のボタンだけが出る（リリースノートの本文は出ない。ダイアログの幅は内容で変わらない）。**映像と音声は止まらない**。設定 > その他 の「現在のバージョン」も v1.0.0 になっている
- [ ] ボタンは 2 段で、上の段に「リリースノートを見る」、少し隙間を空けて下の段に「更新する」「後で」「このバージョンは通知しない」の順に並ぶ。言語を English にしても同じ段組みで、下の段の 3 つが 1 行に収まる
- [ ] 「リリースノートを見る」を押すと、既定のブラウザでその版のリリースページが開き、**ダイアログは閉じない**。続けて「更新する」「後で」「このバージョンは通知しない」が押せる
- [ ] 「後で」を押すとダイアログが閉じ、再起動するとまた出る
- [ ] 「このバージョンは通知しない」を押して再起動すると、ダイアログが出ない。設定ファイルの `[update]` に `skipped_version = "X.Y.Z"` があり、設定 > その他 の「更新」の欄に「通知しないバージョン: vX.Y.Z」と「解除」が出ている
- [ ] 「解除」を押して「適用」し、再起動するとまたダイアログが出る
- [ ] 設定 > その他 の「新しいバージョンがあれば起動時にダイアログで知らせる」を外して「適用」し、再起動すると、ダイアログは出ず、「更新」の欄にだけ「新しいバージョン vX.Y.Z があります」と出る
- [ ] 「起動時に更新を確認する」を外して「適用」し、再起動すると、ダイアログは出ず、欄は「まだ確認していません」のまま。ログに問い合わせの行（「更新の確認を始める」）が無い
- [ ] その状態で「更新を確認」を押すと、「確認中...」のあと「新しいバージョン vX.Y.Z があります」になる（**ダイアログは出ない**）。確認中はボタンが押せない
- [ ] 「リリースページを開く」を押すと、見つかった版（まだ確認していなければ最新）のリリースページが開く
- [ ] 通常の起動では、ダイアログが出ず、「更新を確認」を押すと「最新です」になる
- [ ] `releases/latest` の応答を保存した JSON（`gh api repos/Mui-MuiMui/Capturecard_Viewer/releases/latest > latest.json` で作れる）の `tag_name` を `v9.9.9` に書き換え、`set CAPTURECARD_VIEWER_UPDATE_API_URL=file:///C:/work/latest.json` を指定して通常の版で起動すると、「新しいバージョン v9.9.9 があります」のダイアログが出る。ネットワークを切っていても同じ
- [ ] `CAPTURECARD_VIEWER_UPDATE_API_URL` に存在しないファイル（`file:///C:/nothing.json`）を指定して起動すると、起動は続き、トーストは出ず、「更新」の欄に「確認できない: テスト用の Release の JSON を読めない: ...」が出る。続けて「更新を確認」を押すと、今度はトースト「更新できません: ...」も出る
- [ ] ネットワークを切った状態（機内モードや LAN ケーブルを抜く）で起動しても、**起動は待たされず、映像はこれまでどおり出る。** **トーストは出ない。** 数秒以内に「更新」の欄に「確認できない: 理由」が出て、ログに WARN が残る。その状態で「更新を確認」を押すと、「更新できません: ...」のトーストも出る
- [ ] ネットワークを切った状態で起動直後（確認中）に閉じても、待たされずにすぐ終了する
- [ ] 言語を English にすると、ダイアログと「更新」の欄が英語で出る
- [ ] `[update]` の無い設定ファイル（この版より前）で起動すると、確認も通知もする設定（2 つのチェックが入った状態）になり、他の設定は保たれる

### 更新の適用

「更新する」からのダウンロード・照合・差し替え・再起動。**公開済みの v1.1.0 には自動更新用のファイル（単体の exe と `SHA256SUMS.txt`）が無い**ので、実際の Release で最後まで通せるのは、それらを添付した次のリリース（v1.2.0 以降）から。それまでは「資産が無い」の文言と、ローカルのファイルを資産にした手順で確かめる。

**資産が無い版と書けないフォルダ**（版を差し替えて起動）

- [ ] 「更新する」を押すと、ダイアログが「更新できませんでした」に変わり、「このバージョンには自動更新用のファイルがありません。リリースページから手動で更新してください」と「リリースページを開く」「閉じる」が出る。画面下部に「更新できません: ...」のトーストも出る。exe の隣に `.new` は作られない
- [ ] 設定 > その他 の「更新」の欄の「更新する」を押しても同じになる（起動時のダイアログを「後で」で閉じてから試す）
- [ ] exe を管理者で `C:\Program Files\capturecard_viewer\` にコピーし、そこから通常のユーザーで起動して「更新する」を押すと、「このフォルダには書き込めないため自動更新できません。リリースページから手動で更新してください」が出る（資産の無い版でもこちらが先に出る）。`C:\Program Files\capturecard_viewer\` には何も増えない。確かめたらフォルダを消す

**ローカルのファイルを資産にして最後まで通す**（ネットワークは要らない）

作業用のフォルダ（例: `C:\work`）に、いまビルドした exe を「新しい版」として `C:\work\release` に資産名（`capturecard_viewer.exe`）で置き、その hash の `SHA256SUMS.txt` と、それらを資産に持つ Release の JSON を作る。差し替えられる側として、同じ exe を `C:\work\app` にもコピーする。PowerShell で次のとおり。

```powershell
$w = "C:\work"
New-Item -ItemType Directory -Force "$w\app", "$w\release" | Out-Null
Copy-Item target\release\capturecard_viewer.exe "$w\app\capturecard_viewer.exe"
$exe = "capturecard_viewer.exe"
Copy-Item target\release\capturecard_viewer.exe "$w\release\$exe"
$hash = (Get-FileHash "$w\release\$exe" -Algorithm SHA256).Hash.ToLowerInvariant()
[IO.File]::WriteAllText("$w\SHA256SUMS.txt", "$hash  $exe`n")
@{ tag_name = "v9.9.9"; html_url = "https://github.com/Mui-MuiMui/Capturecard_Viewer/releases/tag/v9.9.9"; body = "テスト用"; assets = @(
    @{ name = $exe; browser_download_url = "file:///$w/release/$exe" },
    @{ name = "SHA256SUMS.txt"; browser_download_url = "file:///$w/SHA256SUMS.txt" }) } |
  ConvertTo-Json -Depth 3 | ForEach-Object { [IO.File]::WriteAllText("$w\latest.json", $_) }
```

コマンドプロンプトで `set CAPTURECARD_VIEWER_UPDATE_API_URL=file:///C:/work/latest.json` をしてから `C:\work\app\capturecard_viewer.exe` を起動する。

- [ ] 「新しいバージョン v9.9.9 があります」のダイアログで「更新する」を押すと、「更新しています」に変わって進み具合が出たあと、ウィンドウが閉じて新しい exe が起動する。起動した新しい exe でも同じ指定が効いているので、またダイアログが出る（「後で」で閉じてよい）
- [ ] ログ（`%AppData%\capturecard_viewer\logs`）に「更新の exe を照合した」「exe を差し替えた」「新しい版を起動した」が並び、新しい方のログに「前回の更新の残りを消した」が出る。数秒後には `C:\work\app` に `capturecard_viewer.exe.old` も `.new` も無い
- [ ] 閉じる前に変えた設定（ウィンドウの位置や音量）が、起動した新しい exe に引き継がれている
- [ ] `C:\work\SHA256SUMS.txt` の hash を 1 文字変えてからもう一度「更新する」を押すと、「ダウンロードした exe の SHA-256 が SHA256SUMS.txt と合わない」が出る。`C:\work\app\capturecard_viewer.exe` はそのままで（更新日時が変わらない）、`.new` は残らない
- [ ] `SHA256SUMS.txt` の hash を大文字にしても、更新は通る
- [ ] 上の PowerShell の `$exe` を 1.2.0 の旧名 `"capturecard_viewer-v9.9.9-windows-x64.exe"` にして作り直しても、更新は通る。差し替わった exe の名前は `C:\work\app\capturecard_viewer.exe` のまま
- [ ] 更新中も映像と音声は止まらない（ローカルのファイルでは一瞬で終わるので、次のリリースで確かめる）

**次のリリース（自動更新用のファイルを添付した版）で確かめること**

- [ ] 1.2.1 の公開後、1.2.0 で「更新する」を押すと「このバージョンには自動更新用のファイルがありません。リリースページから手動で更新してください」が出る（1.2.0 は版付きの名前しか探さないため。想定どおりの動き）。Release の資産が `capturecard_viewer.exe` と `SHA256SUMS.txt` の 2 つである
- [ ] 1.2.1 以降の版（`capturecard_viewer.exe` を探す版）を書き込めるフォルダに置いて起動し、その次の版が出たあとで「更新する」を押すと、進み具合が % で進み、終わるとウィンドウが閉じて新しい版が起動する。設定 > その他 の「現在のバージョン」が上がっている
- [ ] ダウンロード中に「キャンセル」を押すと、ダイアログが閉じ、exe の隣に `.new` が残らない（数秒以内に消える）。exe は元の版のまま
- [ ] ダウンロード中にアプリを閉じると、待たされずに終わる。次の起動で `.new` が消える
