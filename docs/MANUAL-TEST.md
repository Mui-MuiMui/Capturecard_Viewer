# 手動テストチェックリスト

キャプチャーデバイスを接続した実機でのみ確認できる項目をまとめる。リリース前に一通り実施する。

自動テストの方針は `.claude/skills/testing-conventions/SKILL.md` を参照。

## 実施環境の記録

結果を残すときは以下も併記する。デバイス依存の不具合が多いため、環境が分からない結果は役に立たない。

- Windows のバージョン
- キャプチャーボードの製品名
- 選択したフォーマット / 解像度 / フレームレート
- オーディオ入力デバイス名

## 起動と表示

- [ ] 起動して 1〜2 秒以内に映像が表示される
      （固定の 2 秒待ちを廃止したので、以前より短くなっていること。実測では起動から接続完了まで 0.70〜0.87 秒、映像が出るまで 1.06〜1.12 秒）
- [ ] 音声が出力される
- [ ] 映像と音声のズレが許容範囲内である
- [ ] 1080p のソースで、黒い部分が灰色に浮かず、彩度が不自然に見えない
      （HD は BT.709、SD は BT.601 で変換している。解像度を 720x480 などの SD へ切り替えても同様に見えること。
      色の厳密な検証には既知のパターン映像を入力する必要があり、仮想カメラを使った検証はバックログの調査タスクに委ねている）
- [ ] ウィンドウのアイコンが既定の赤い四角ではなく、正しいアイコンになっている
- [ ] exe をショートカット経由で起動しても上記が同じ結果になる
- [ ] 作業ディレクトリが exe の場所と異なっても、アイコンが正しく表示され、効果音が鳴る
      （コマンドプロンプトで `cd C:\` してから exe を絶対パスで起動する）

## デバイス操作

- [ ] 右クリック > デバイス再接続 で映像と音声が復帰する
- [ ] キャプチャーボードの USB を抜き差ししたあと、デバイス再接続で復帰する
- [ ] キャプチャーボードを抜いた状態で起動し、あとから挿すと、操作しなくても映像と音声が出る
      （繋がるまで自動で再試行する。間隔は最大 5 秒なので、挿してから 5 秒ほど待つ）
- [ ] 上の再試行の間、ウィンドウが数秒固まらない
      （ドラッグで動かす、右クリックメニューを開く、ダブルクリックでフルスクリーンにする、がすべて反応すること。
      タスクマネージャーで「応答なし」にならないこと。
      デバイスを開く処理は UI スレッド上に残っているため、1 回の試行で最大 0.5 秒ほど描画が飛ぶことはある）
- [ ] 設定画面でデバイスを切り替えたときの反映が、従来どおり即座に行われる
      （再試行の待ち時間を挟まずに切り替わること）
- [ ] 設定画面でビデオデバイスを切り替えると、その機器の映像に変わる
- [ ] 設定画面でビデオデバイスを切り替えても画面が固まらず、映っている映像も止まらない
      （対応形式の取得中はデバイス名の下にスピナーと「対応形式を取得中...」が出る。取得が終わると解像度とフレームレートの選択肢が増える）
- [ ] 設定画面でビデオデバイスを切り替えると、解像度とフレームレートも新しいデバイスが対応する値へ入れ替わる
      （切り替え前の値に最も近い組み合わせが選ばれる。新しいデバイスが同じ組み合わせに対応していれば、その値のまま残る。
      対応形式の取得が終わるまでは前のデバイスの値が出たままで、取得が終わった時点で入れ替わる。
      取得に失敗した場合は入れ替わらない）
- [ ] 上で入れ替わった解像度・フレームレートが、それぞれの選択肢の中に実在する
      （選択肢に無い値が選択中として表示されないこと。表示と実際にキャプチャーされる設定が食い違う原因になる）
- [ ] 起動直後に設定画面を開くと、保存済みデバイスの解像度とフレームレートが選べる
      （起動時に先読みしている。取得が終わる前に開いた場合はスピナーが出て、終わり次第選択肢が増える）
- [ ] 対応形式の取得に失敗すると理由が表示され、「再取得」ボタンで取り直せる
      （キャプチャーボードの USB を抜いた状態でデバイスを選ぶと再現できる。挿し直して「再取得」を押すと選択肢が出る）
- [ ] 設定画面でオーディオ入力デバイスを切り替えると、その機器の音声に変わる
- [ ] 設定画面でオーディオ出力デバイスだけを切り替えると、その機器から音が出る
      （出力先だけの変更では再接続が走らない不具合を直した。以前は切り替えても古い出力先で鳴り続けた）
- [ ] 設定画面でサンプリングレートを 8000Hz にすると音質がこもり、48000Hz に戻すと元に戻る（デバイスが両方に対応している場合）
- [ ] サンプリングレートを変えたあと、音程と再生速度が変わらない（入力と出力で別の値が選ばれていないこと。ずれる場合は既知の不具合「入出力でレートが異なると音が崩れる」に該当する）
- [ ] デバイスが対応していないサンプリングレートを選んでも、音が止まらず最も近い値で鳴り続ける

## ウィンドウ操作

- [ ] ダブルクリックでフルスクリーンになり、もう一度で元に戻る
- [ ] 切り替えたとき「フルスクリーン ON / OFF」が画面下部中央に出て、1 秒ほどで消える
      （表示位置を左上から下部中央へ移した。情報表示をオンにしていても重ならないこと）
- [ ] フルスクリーンから戻ったとき、元のウィンドウサイズと位置が復元される
- [ ] 映像部分のドラッグでウィンドウが移動する
- [ ] 右クリック > 画面ドラッグ移動 をオフにすると、ドラッグで移動しなくなる
- [ ] 右クリック > 最前面表示 で他のウィンドウより前面に出る
- [ ] 右クリック > アスペクト比を維持 のオン / オフで表示が変わる
- [ ] 右クリック > 情報表示 をオンにすると、映像の左上に FPS・ばらつき・デコード時間・解像度が出る
- [ ] 情報表示の FPS が、設定したフレームレートとおおむね一致する
- [ ] 情報表示をオンにしたままフルスクリーンにしても表示が続く
- [ ] 情報表示の上でドラッグや右クリックをしても、ウィンドウ移動とコンテキストメニューが従来どおり働く
- [ ] 右クリック > 情報表示 をオフにすると表示が消える
- [ ] 情報表示をオンにして終了し、再起動すると表示されたままになっている
- [ ] ウィンドウを移動・リサイズして終了し、再起動すると位置とサイズが復元される
- [ ] フルスクリーンのまま終了して再起動すると、フルスクリーンに入る前の通常サイズで復元される
- [ ] 保存位置が画面外の場合に画面内に表示される（モニタ構成を変えて確認）
      サブモニタへウィンドウを寄せて終了 → サブモニタを外して起動、または
      `default-config.toml` の `last_window_pos` を `[-5000.0, 300.0]` に書き換えて起動する
- [ ] ウィンドウを表示領域が潰れるまで小さくしても、落ちたり表示が乱れたりしない
- [ ] 最小化してから元に戻すと、映像が元どおり表示される

## 音量

- [ ] マウスホイールで音量が 10% ずつ変わる
- [ ] 音量 0% で無音になる
- [ ] 音量 200% まで上げられる
- [ ] 音量を変えて終了し、再起動しても保持されている

### 音量の表示（OSD）

- [ ] マウスホイールで音量を変えると、画面下部中央に「音量: N%」とバーが出る
- [ ] 表示される数字が、右クリックメニューの「音量: N%」と一致する
- [ ] ホイールを回し続けている間は表示が出たままで、手を止めてから 1.5 秒ほどで消える
- [ ] 100% の位置に目盛りが出ており、100% を超えるとその先のバーの色が変わる
- [ ] 音量 0% ではバーが空、200% ではバーが端まで埋まる
- [ ] 右クリックメニューの音量スライダーを動かしても同じ表示が出る
- [ ] 設定画面で音量に関わる操作をして「適用」か「OK」を押し、音量が変わった場合に表示が出る
      （音量を変えずに適用したときは出ないこと。2 秒ごとの設定の再適用で出っぱなしにならないこと）
- [ ] キャプチャーデバイスを抜いて「映像信号がありません」の状態にしてから音量を変えても、表示が 1.5 秒ほどで消える
      （映像が届かず再描画が止まる状態でも消えること。消えずに残る場合は再描画の予約が効いていない）
- [ ] 情報表示（統計オーバーレイ）をオンにしていても、音量の表示と重ならない
- [ ] 音量の表示が出ている間に、その真上あたりで映像をドラッグ・右クリックしても、ウィンドウ移動とコンテキストメニューが従来どおり働く
- [ ] フルスクリーンでも同じ位置に表示される
- [ ] 設定 > 音声パススルー のチェックを外すと音が止まる
- [ ] チェックを戻すとすぐに音が戻り、止めていた間の古い音が遅れて出てこない
- [ ] 音声パススルーを無効にしたまま終了し、再起動しても起動直後に音が出ない

## スクリーンショット

- [ ] ホットキー（既定 F5）で保存される
- [ ] 撮影した瞬間に映像がカクつかない（動きの速い映像を出しながら撮ると分かりやすい）
- [ ] ホットキーを連打しても、押した回数だけファイルが保存される
- [ ] 撮影した直後にアプリを閉じても、最後の 1 枚が壊れずに保存されている
- [ ] 保存先が設定した フォルダになっている
- [ ] 保存形式が JPEG のとき、ファイル名が `年-月-日_時-分-秒-ミリ秒.jpg` になっている
- [ ] 設定 > 保存形式で PNG を選ぶと `年-月-日_時-分-秒-ミリ秒.png` で保存され、画像ビューアで開ける
- [ ] PNG のときは「JPEG 品質」のスライダーが操作できない
- [ ] JPEG の品質を 10 と 100 で撮り比べると、ファイルサイズがはっきり変わる
- [ ] 保存形式を PNG にして終了し、再起動しても PNG のままになっている
- [ ] 保存形式を追加する前の設定ファイル（`format` の行が無い状態）で起動しても JPEG で保存される
- [ ] 効果音が鳴る
- [ ] 効果音の音量設定が反映される
- [ ] 設定画面の「テスト再生」で効果音が鳴る
- [ ] ホットキーを別のキーに変更すると、新しいキーで動作し、古いキーでは動作しない
- [ ] 他のアプリにフォーカスがある状態でもホットキーが効く

### ホットキー設定ダイアログ

- [ ] キャプチャ開始後に Ctrl や Shift を単独で押しても確定せず、「キー入力待機中...」のままになる
- [ ] キャプチャ開始後に Ctrl+Shift や Ctrl+Shift+Alt を押しても確定しない
- [ ] 上記の状態から続けて A を押すと `Ctrl+Shift+A` のように確定する
- [ ] 修飾キーなしで F5 を押すと `F5` が確定する
- [ ] 数字キー（例: `Ctrl+Shift+9`）を設定でき、そのキーでスクリーンショットが撮れる
- [ ] 確定したホットキーで OK を押すと、登録に失敗せずそのキーで動作する

## 設定画面

各ボタンの意味は `README.md` の「設定」を参照。設定画面での編集はドラフトとして扱われ、「適用」か「OK」を押すまで動作中のアプリにも設定ファイルにも影響しない。「適用」と「OK」の違いは画面を閉じるかどうかだけ。

唯一の例外は効果音の「テスト再生」で、適用前でも編集中の音量で鳴る。効果音のファイル自体は適用するまで差し替わらない。

- [ ] OK を押すと設定が反映され、再起動後も保持される
- [ ] 適用を押すと画面は閉じずに設定が反映され、そのまま終了・再起動しても保持される
- [ ] 適用を押さずにキャンセルを押すと、編集した内容が反映されない
- [ ] 適用を押したあとキャンセルを押しても、適用した内容は反映されたまま残る
- [ ] 設定ウィンドウを × で閉じると、編集した内容が反映されない（キャンセルと同じ）
- [ ] 設定ウィンドウを × で閉じたあと、もう一度開いてキャンセルしても、意図しない値に巻き戻らない
- [ ] 設定画面で値を編集しただけ（適用も OK も押さない）の状態でウィンドウを移動・リサイズし、キャンセルしてから終了・再起動しても、編集した値が保存されていない
- [ ] 設定画面を開いたままウィンドウを移動・リサイズしてから OK を押しても、ウィンドウの位置とサイズが巻き戻らない
- [ ] 設定画面でホットキーを変更しても、適用か OK を押すまでは古いホットキーが効く
- [ ] 効果音の音量スライダーを動かしてテスト再生すると、適用前でもその音量で鳴る
- [ ] 設定画面を開いたまま映像上でホイール操作をして音量を変え、設定画面で適用か OK を押しても、音量が巻き戻らない

### 設定ファイルの復帰

`%AppData%\capturecard_viewer\config\default-config.toml` をテキストエディタで編集して確認する。確認前に元のファイルを控えておくこと。

- [ ] 行を 1 つ削って起動すると、削った項目だけが既定値になり、他の設定は保持される
- [ ] `[ui]` のようにセクションごと削って起動しても、他のセクションの設定は保持される
- [ ] TOML として壊れた内容（`volume = ` のように値を欠いた行など）にして起動すると、既定値で起動し、同じフォルダに `default-config.toml.bak` が作られる
- [ ] 続けてもう一度壊して起動すると `default-config.toml.bak.1` が作られ、先の `.bak` の内容が残っている

## 現時点で既知の不具合により失敗する項目

以下は実装側の不具合が原因で落ちる。**対応する修正が入ったら、この節から外して上のチェックリストに統合する。**

- [ ] 設定 > チャンネル数 の変更が反映される
  → デバイスが対応する中で最も近い値へ寄せる実装になっているが、WASAPI はミックスフォーマットのチャンネル数しか報告しないため、実際にはデバイスの既定値しか選べない。選択肢をデバイスの能力から生成する作業がバックログにある
- [ ] 設定 > フォーマットで MJPEG や RGB24 を選ぶと、その形式で動作する
  → 現状は常に YUY2 で開かれる
- [ ] F12 をホットキーに設定できる
  → 他システムとの競合により登録できない（README の既知問題）

## 長時間動作

リリース前に一度は確認する。

- [ ] 1 時間以上連続で表示し続けても、映像が止まらない
- [ ] 同上の条件でメモリ使用量が増え続けない
- [ ] 同上の条件で音声にノイズやズレが蓄積しない
