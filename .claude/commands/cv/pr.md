# /cv:pr — PR 作成

開発フローの 4 段目。書式はすべて `.claude/skills/naming-conventions/SKILL.md` に従う。**このファイルに書式を再掲しない。**

## 前提の確認

`/cv:review` が通っていることを確認する。通っていない、または実行していない場合は、その旨を伝えて `/cv:review` を先に実行するか確認する。

## 手順

### 1. 差分を確認する

コミット前に変更内容を必ず目視する。意図しないファイルが混ざっていないか、デバッグ用の一時変更が残っていないかを見る。

### 2. コミットする

`naming-conventions` skill の「コミットメッセージ」に従う。

- Asana タスクがあるなら `Asana:` 行に URL を入れる
- 変更が性質の異なる複数のまとまりなら、コミットを分ける

### 3. push して PR を作成する

`naming-conventions` skill の「PR タイトル」「PR 本文」に従う。

PR 本文を `gh pr create` に渡すとき、ヒアドキュメントに `git` という語が含まれると worktree 分離の保護に引っかかることがある。その場合は本文を一時ファイルに書いて `--body-file` で渡し、作成後に削除する。

### 4. Asana と相互リンクする

`~/.claude/skills/asana/SKILL.md` に従って、タスクへ PR の URL をコメントする。

- ブランチ名と変更の要点を添える
- タスクの一部だけを実装した PR なら、その旨と残りのスコープを明記する
- 対応するタスクがない場合は、ここで登録するか確認する

### 5. 報告する

- PR の URL
- Asana へコメントしたタスク
- ユーザーに実機確認を依頼する項目（`/cv:review` で挙げたもの）

## マージ後

ユーザーがマージしたら、以下を行う。

1. `main` を同期する
2. worktree とブランチを削除する（ローカルとリモートの両方）
3. Asana タスクを完了にする。**部分実装だった場合は完了にせず、残りをコメントする**

具体的なコマンドは `naming-conventions` skill の「PR を出したあとにやること」を参照。

## やらないこと

- マージ（ユーザーが行う）
- auto-merge の有効化
- ユーザーの確認なしにタスクを完了にする
